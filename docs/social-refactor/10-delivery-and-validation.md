# 10 交付与验证

[总纲](README.md) · [当前开发指南](../development.md) · [当前约束](../../AGENTS.md)

本文维护里程碑完成条件、验证场景与待细化决策。实施状态见 [已完成](completed.md) / [尚未完成](pending.md)，执行顺序见 [TODO](TODO.md)。

## 1. 实施原则

按可运行的业务链路交付，类型、数据库、事件、两条 GUI backend 与界面在对应里程碑同步落地。完成某个 crate 编译不等于完成对应产品阶段。

架构取舍遵守 [新架构优先与兼容边界](README.md#新架构优先与兼容边界)。保护数据和成熟基础能力，允许替换旧业务结构与 API；已实现的 M0 接口可随用例验证调整，持久化变化配套版本迁移。

按用户确定的顺序，先交付 U0：用明确的模拟模式完成 Web 导航、聊天、通讯录与详情交互，再由 M0 确认 Rust 契约和持久化，M1/M2 接入真实业务。U0 使用简化的前端 SocialApi 与本地快照，不代替目标持久事件协议；接入时按共享 Rust DTO 调整。当前范围与 2026-10-08 验证见 [Web 预览说明](08-frontend-and-desktop.md#当前-web-交互预览)。

每次重构说明保留和改变的行为，同步修改当前规则，不能把“规划中”悄悄改写为“已经支持”。API、数据库和模型请求的实际契约以实现与验收共同确认。

### 按业务链路分批实施

已确认的实施方式：先统一整个项目的目标结构，再在 M1–M3 内分批完成可运行的业务链路。一次重写整个项目会延后产品反馈，扩大故障定位、评审与验证范围；一直按领域、存储、Runtime、API、界面逐层铺完，也会让接口在真实使用前过早固定。

M0 已提供必要的领域与存储基础，后续每批围绕一个实际场景推进，所需层次一起修改。局部可以大幅重写；代码量和旧接口兼容程度不作为拆批依据。只补当前场景所需能力，后续摘要、长期记忆与调度仍按 M2/M3 扩展，不提前建立空框架。

M1 按以下业务链路拆批，不改变里程碑完成条件；各批当前完成状态只在 [TODO](TODO.md) 勾选：

| 批次 | 可体验链路 | 对应验证 |
| --- | --- | --- |
| 1：一个 AI 的长期私聊 | 创建联系人与绑定 → 打开唯一私聊 → 保存真人消息 → 准备近期上下文与来源快照 → 模拟 provider 生成 → 原子收尾 → Web 显示并重连读取 | 独立临时库、真实 HTTP、模拟模型、基础失败/中断收尾与历史恢复 |
| 2：群聊与多 AI | 独立群与成员 → @指定 AI → 确定性队列 → 顺序回复，生成期间继续保存真人输入 | 三个 AI、空间隔离、入群前后完整共享历史与队列顺序 |
| 3：修订与交谈控制 | 编辑消息 → 依赖失效；取消/暂停/结束 → 活动运行与队列收尾 | 后续历史保留、来源版本变化、停止与完成竞争、崩溃恢复 |
| 4：双适配与阶段收尾 | 实时 IPC / Tauri 接入 → 账号管理与联系人关系拆分 → 独立执行配置 → 共用界面现代化 → 完整验收 | M1 全部条件、双适配行为与管理权限一致及受影响平台基线 |

Web 优先用于迭代和验证，HTTP/IPC 共享同一 Rust 业务契约；Tauri 在 M1 内接入。基础失败收尾随首条链路实现，后续批次扩大异常与竞争覆盖，不能等到最后才保证消息落盘和运行终态。

每批检查实际调用链是否遵守目标结构，再运行受影响的用例、存储、传输与界面验证。新语义需要改变旧断言时，同步更新调用与测试；持续维持数据完整性、凭据边界、协议、worker、事务收尾与平台行为。旧接口适配只留在边界，下一批沿已验证的社交用例扩展。

## 2. M0：领域与持久化骨架

交付：新增 social 类型（包括意识系统的范围、来源与快照契约）、共享事件 DTO、SocialStore 接口、SQLite schema、统一目录锁、只读旧格式导入器与 mock/fake clock 基础。

顺序：

1. 确认 ID、revision、sequence、状态枚举和依赖方向。
2. 验证 Rust SQLite 驱动在 Windows MSVC/Linux 的构建、备份、WAL 和错误处理。
3. 实现关键原子操作、命令回执与持久变更引用。
4. 实现 schema 迁移与旧 JSON 预览/导入，保持源数据不变。
5. 在独立临时目录验证锁、崩溃、幂等和失败注入。

完成条件：旧数据导入两次结果一致；损坏/冲突不静默修复；关键事务失败没有部分成功；已有窗口、配置和旧协议测试保持通过。M0 不宣称 GUI 已转型。

## 3. M1：身份与私聊、群聊

交付：SocialFeature 生命周期、独立 AI 账号与真人一致的账号详情、公开/内部设定分离、创建者的初始管理员身份及授予其他管理员、管理员自己的角色管理页面与登录 AI 账号查看、关系级联系人移除/重新添加与管理员账号停用/恢复、独立执行配置、私聊/群聊/成员、消息发送/修订/撤回、@队列、取消/暂停/结束、意识系统基本上下文，以及新 GUI 和双 backend。远程认证服务器、多人联网与同步仍留待后续；屏蔽单独添加。当前社交无工具执行。明确工具授权按具体需求独立实施，不作为本阶段前置；启用时须验证授权撤销、既有 worker 与终态配对。ConsciousnessService 在此阶段读取档案、可见近期原文并形成预算内 PreparedContext 与来源快照；无需摘要或长期记忆即可完成回答。

先完成确定性 mentioned_only，不引入自动相关性接话。建立持续订阅和游标补齐，发送不再预建回答；AI 生成时允许真人继续发送。

完成条件：一个真人与三个 AI 的身份和发言清楚，账号详情的共同内容与结构一致，内部设定不出现在公开资料；初始管理员授予的管理员能管理与登录查看，非管理员被业务层拒绝，查看不超出 AI 自身范围且实际操作者可识别；移除后仍可私聊与共同群互动，重新添加沿用原私聊，全局停用仅由管理员触发并保留数据，恢复不重放旧队列；@多个 AI 顺序可控，输入连续保存，修改早期消息保留后续历史，暂停与完成竞争不发布停止后的成功；独立生成参数可验证，社交执行不开放工具，HTTP/IPC 契约和受影响平台行为一致。

M1 同步修订 README、AGENTS 的当前定位、代码地图和无模型发送规则。新业务未完成前保持现有规则，不能提前据规划修改运行事实。

## 4. M2：意识系统完善

当前三批 [显式记忆](m2-explicit-memory.md)、[窗口分段摘要](m2-window-summaries.md)、[群话题接续](m2-cross-window-continuation.md) 已完成。具体边界与验证以批次记录和当前模块说明为准。

交付：在 M1 的 ConsciousnessService 上加入简单显式记忆条目、关系/群范围、来源版本、窗口分段摘要及来源版本、跨窗口依赖校验、群聊接续私聊的 ContextReference、遗忘标记，以及聊天详情和联系人详情中的记忆/摘要面板。基本上下文构造与预算沿用 M1，不另起一套执行链路。

先实现手动添加/编辑/遗忘与权限筛选，自动候选提取和复杂后台巩固不作为 M2 完成前置。摘要生成及未来记忆提取使用明确的模型绑定和独立预算，不能暗中调用另一付费模型。后续加入提取时同时实现候选确认和已知来源遗忘抑制。

完成条件：完整窗口记录持续保留；近期上下文由软件构造且 provider 续接链各空间隔离；摘要按需生成、按请求读取并可追溯；共同群话题能以相关来源接续唯一私聊；模型更换后记忆归属正确；私聊记忆不进入群请求，当前群成员共享加入前后的本群历史；编辑/撤回/遗忘及源权限变化使跨窗口派生内容失效。

先交付消息/话题锚点接续，不以全局自动语义召回或每 AI 一份综合记忆概览作为 M2 前置。Dreaming 的后台多窗口整理与时效性作为意识系统后续扩展方向，具体算法另行设计，参考 [意识系统扩展说明](03-consciousness.md#8-后续长期记忆扩展)。

## 5. M3：节奏与约定联系

交付：连续输入合并、limited_auto、Bout 等待/空闲结束、轮数/预算限制、一次性 ContactIntent、免打扰、过期与崩溃恢复。

优先由确定性规则实现等待和上限，再验证模型建议是否改善时机。默认主动联系关闭，先支持用户创建的一次性约定；多 AI 自动交谈有限且可随时停止。

完成条件：fake clock 下复现到期、过期、免打扰和时钟变化；退出后不调用模型；重启不重复发布或重放不确定副作用；过期计划不集中补发。实际体验确认初始延迟与自动轮数参数。

## 6. 首版完成后的兼容收尾

梳理旧 ChatFeature、SessionManager、旧 HTTP/chat-event、demo 和 CLI/TUI 依赖。各调用链转入同一用例、有限适配或明确退役后，逐步去除重复业务；保留必要旧格式读取与可验证导入。可以在对应链路切换时先替换冲突的旧实现，不能为了推迟到兼容收尾而限制新架构。

更新 acceptance 脚本和 CI，移除失效断言，保留配置、协议、worker、平台与发布基线。不得通过删除失败测试掩盖持久化或中断回归。

## 7. 验证层次与命令

| 层次 | 主要验证 | 能证明什么 |
| --- | --- | --- |
| 领域 | 身份、成员范围、状态转移、有限参与 | 确定性规则 |
| 存储 | 事务失败、锁、幂等、迁移、杀进程 | 本地持久化与恢复 |
| 执行 | 模拟 provider 的工具/流式/错误/快照 | 模型调用组织与收尾 |
| 传输 | 真实 HTTP 与 IPC DTO 对照、回放/溢出 | 两条适配契约 |
| GUI | 输入保留、状态、重连、暂停、记忆 | 产品交互 |
| 包与平台 | Tauri 构建、实际安装、worker、窗口 | 目标环境与产物 |
| 真实 API | 已授权的付费协议与体验检查 | 指定模型和当时服务行为 |

运行与验收命令统一见 [开发指南](../development.md#检查改动)。社交变更先检查 social/social-feature/storage/events 与受影响传输、前端；影响 Runtime、协议、工具或旧 chat 时补跑对应包。完整里程碑按范围执行 workspace 检查与 Tauri 打包，不把编译、模拟 API 和安装验收混为同一结果。真实 provider 只有明确授权后使用。

## 8. 必须覆盖的端到端场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 同模型创建三个 AI，重复打开私聊 | 身份互不混淆，每个角色私聊唯一，各群独立 |
| A02 | 生成中连续发送 | 消息不丢失，顺序稳定，后续计划有限 |
| A03 | 编辑早期消息 | 后续历史保留，旧来源派生内容失效 |
| A04 | 私聊记忆与群提问相似 | provider 请求中仍无未授权记忆 |
| A05 | 新 AI 入群 | 共享加入前后的完整本群历史；摘要只概括本群，私聊和其他群内容不随入群共享 |
| A06 | 暂停与成功提交竞争 | 停止事务生效后不再发布成功回答 |
| A07 | SSE/IPC 断线与重连 | 无漏消息和重复发布，终态覆盖 delta |
| A08 | 到期计划前进程崩溃 | 安全待办重新评估，已 dispatch 不自动重放 |
| A09 | 后续启用工具时：工具执行中退出 | 子进程终止，草稿与失败配对可恢复 |
| A10 | 磁盘满/事务失败 | 无伪成功或内存部分更新 |
| A11 | 旧数据重复导入 | 计数、UUID 与来源映射稳定，原文件不变 |
| A12 | 目录冲突和迁移失败 | 锁不降级，错误带实际路径 |
| A13 | 更换模型或热更新 | 身份不变，在飞路由来自同一快照 |
| A14 | 自动 AI 互相触发 | 达到轮数/预算上限后停止 |
| A15 | 遗忘后回放，后续加入自动提取 | 事件不带旧原文，已知来源不恢复条目 |
| A16 | Web/Windows/Linux | IPC、窗口、路径与安装标识基线保持 |
| A17 | 同 AI 私聊与多个群，生成摘要 | 请求上下文按空间隔离，原记录完整保留 |
| A18 | 消息/通讯录与两种详情切换 | 无记忆主导航，关系记忆一致，群记忆归属明确 |
| A19 | 共同群话题转到私聊 | 使用原唯一私聊，只引用相关共同可见来源，带入正确发送者/时间，不回传私聊内容 |
| A20 | 源群权限/消息版本变化 | 跨窗口旧引用、摘要与缓存失效；提交回答前复核来源；无源访问权不能自动召回 |
| A21 | 摘要阈值、分段与后台失败 | 短聊天可跳过摘要，近期更新不遗漏，失败不撤销消息保存或伪造完整历史理解 |
| A22 | M1/M2 意识系统逐步启用 | M1 无摘要/长期记忆仍可回复，M2 沿用同一服务与存储，双适配行为一致 |
| A23 | 摘要更新与源变更竞争 | 旧任务不能写入有效旧摘要；变更事件使详情读取当前状态 |
| A24 | 结束 Bout 与未来约定 | 本 Bout 队列/活动运行停止，不再发布成功回复；独立未来意图保留 |
| A25 | 遗忘条目与撤回来源 | 两种范围分别生效，遗忘不伪报完整历史已删除，撤回使所有源依赖失效 |
| A26 | 授予/撤销管理员与账号视角 | 共同公开 DTO 不含内部设定，非管理员及撤销后旧回执均被拒绝；只读视角只读 AI 自身成员范围，保留实际操作者 |
| A27 | 生成中移除联系人、继续聊天、重新添加 | 只改变自己的通讯录，运行/队列与共同群继续，重新添加沿用原私聊；管理员停用另外收尾运行 |
| A28 | 准备期间与运行期间修改执行配置 | 开始前拒绝过期档案/绑定版本；已开始运行保留原快照，新运行使用新配置，身份与历史不变 |
| A29 | 同模型 AI 使用不同温度/输出上限；非法组合、重启与双适配保存 | 管理员维护内部参数，不进入公开资料；留空不继承全局设置，4096 等显式值不压回 1024；上下文预留一致，失败无部分提交，旧绑定与命令摘要兼容 |

测试使用合成档案、临时数据和模拟 provider，禁止复制真实个人会话或配置到 fixture、CI 或发布资源。测试应检查结果和边界，避免只镜像实现。

## 9. 后续多人阶段

本地账号管理、管理员授予及账号视角查看归 M1；后续多人联网仍需单独设计远程认证、跨设备授权与成员邀请、云端存储、消息同步冲突、离线推送、滥用治理和服务费用。首版稳定 ID 与事件契约提供扩展起点，不意味着这些联网功能已经实现或可以无成本接入。
