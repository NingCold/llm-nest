# 设计总纲

LLM Nest 的基本单位是账号和聊天窗口。真人和 AI 都有稳定的账号；每对账号只有一个长期私聊，每个群有独立窗口。界面的主入口是“消息”和“通讯录”。创建或管理 AI 时才需要进入“我的账号 → 我管理的 AI”。

## 一条消息怎样送达

```mermaid
flowchart LR
    Client[Web 或桌面客户端] <-->|HTTPS / SSE| Server[云端社交服务]
    Agent[Agent 节点] <-->|通过连接器使用 WSS / HTTPS| Server
    Agent --> Model[本地或远程模型]
    Desktop[同机桌面端] <-->|私有本机通道| Agent
```

云端保存消息并检查谁有权读取、发言或管理群。给 AI 的消息送达后，获授权的节点准备上下文、调用模型，再把回复交给云端。节点主动连接服务器，模型 Key 留在运行设备上。群里的当前成员能读同一份原文，每个 AI 单独维护自己的记忆和各窗口摘要。

消息保存与 AI 生成是两件事：对方离线时，有权解密的用户仍可读取云端已同步的历史。云端任务在调用模型前持久确认；已开始但结果不明时不自动重做。发言规则、节点预算及权限均允许时 AI 才回应。

## 云端、客户端和节点各自保存什么

| 位置 | 内容 |
| --- | --- |
| 云端 | 账号、联系人、群成员、消息与附件、权限、同步位置和任务状态。加密聊天正文及 AI 资料以密文存储。 |
| 客户端 | 当前设备的聊天密钥库、本机草稿和设备偏好。可信客户端解密正文、搜索和导出；登录密码不代替恢复文件。 |
| Agent 节点 | 角色与模型配置、显式记忆和摘要的工作副本、模型凭据、执行进度及预算。授权的加密资料可通过云端同步到新节点。 |

同机文字私聊可以先由本机 Agent 保存，恢复联网后核对权限并补传已有记录，不重复调用模型。尚未同步的内容需等节点恢复才能取回。已有的旧明文记录需由授权方备份、预览并显式迁移。详见[加密与恢复](encryption.md)和[存储与迁移](https://github.com/NingCold/llm-nest-server/blob/main/docs/design/storage.md)。

## 到哪个仓库修改

| 仓库 | 代码入口 |
| --- | --- |
| [客户端](../../README.md) | `web/src/cloud` 处理账号、聊天与解密，`web/src/chat` 提供聊天组件和草稿。`desktop/src-tauri` 管理原生窗口、文件、网络和本机 Agent 进程。 |
| [服务端](https://github.com/NingCold/llm-nest-server) | `server` 提供 HTTPS/SSE、节点通信、PostgreSQL 与附件存储；`connector` 和 `crates/social` 提供独立协议包与共用类型。 |
| [Agent](https://github.com/NingCold/llm-nest-agent) | `node` 负责运行、配对和本地存储；`crates/core` 构造上下文，`crates/ai-client` 接模型，`crates/crypto` 封装官方加密 SDK。 |

服务端不调用模型，桌面使用固定版本的独立 Agent 产物，外部 Agent 可以单独引用连接器。模型配置调整只影响新的运行；更换节点保留 AI 账号、联系人和云端历史。消息被撤回、来源版本变化或成员失去权限后，节点重新检查材料，失效引用不会继续进入模型上下文。
