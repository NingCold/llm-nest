# 社交重构路线

[总纲](overview.md) · [交付与验收](10-delivery-and-validation.md) · [当前任务](in-progress.md)

近期目标是完成一个可持续使用的本地人与 AI 社交版本。按完整使用场景交付；技术细项在批次内部完成，新想法先进入[候选清单](pending.md)，不自动延长当前批次。

| 意识与参与（M2 / M3） | 显式记忆、窗口摘要、群话题接续、参与节奏、一次性约定与免打扰的首版范围已完成 |

逐项能力与历史证据统一见[已完成](completed.md)，不再在路线中重复各小批次。普通文件目前只向模型提供元信息，文件正文读取仍是候选能力。

体验收尾已完成，当前集中完成 Windows 平台检查。Linux 于 2026-10-20 按用户要求暂缓，安装任务继续暂缓。验收发现的问题在所属批次内修复。新增格式、召回算法或联网能力进入候选清单，不成为首版的新完成条件。

这两批完成后，再根据实际使用选择下一项产品目标。自动记忆、文档理解、多人社交不是必须依次清空的队列，也不需要全部实现后才能结束首版。

## 批次怎样执行

每批先明确用户能完成什么、做到哪里结束，再一起完成所需的前端、业务、存储、HTTP/IPC、验证和文档。共享契约先确定，互不冲突的实现可交给 GPT-6.1-Sol 并行处理，由主代理整合验收；不需要为每个按钮、接口或测试逐次请用户安排。

只有存在独立可用的交付结果、真实依赖或需要体验反馈时才拆批。遵守[新架构优先](overview.md#新架构优先与兼容边界)，边界保留必要校验，内部避免重复防御和假设性框架。
