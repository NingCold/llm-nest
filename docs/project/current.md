# 当前安排

[已完成](completed.md) · [待验收与候选](backlog.md) · [同机与加密计划](secure-local-plan.md) · [使用指南](../usage.md)

**第二批“私聊、设备恢复与 AI 资料加密”已实现，并通过完整自动验收。** 协议选用 Matrix Olm/Megolm，客户端与 Agent 使用官方 SDK。已有私聊可以显式开启加密，新的文字、AI 流式回复、角色与模型参数、显式记忆和每 AI 的窗口摘要由授权端加解密，服务器保存密文。

登录与解密授权分开：新设备需要可信设备授权或恢复文件，登录密码不能恢复聊天密钥。AI 资料可以在节点离线时保存，客户端断网时保留待同步修改；界面区分云端已保存和节点已应用，版本冲突不会覆盖编辑。正常更换节点先同步资料与历史密钥，新节点建立独立设备，恢复后继续使用同一账号与聊天，不重做旧调用。

第一批的同机文字私聊也已接入同一份密文和密钥投递。使用已准备的登录会话，关闭云端服务后仍可通过本机 Agent 与可用模型继续聊；恢复联网只同步原消息与原结果。桌面重启后的离线重新登录、局域网直连和完整离线社交尚未提供。

协议、离线修改与换节点规则集中在[加密契约](../design/crypto-contract.md)和[加密方案](../design/encryption.md)。实际测试范围见[验证记录](../validation/README.md#私聊与-ai-资料加密验证)，不在每个计划中重复维护测试数量。

**下一步：第三批“完整社交功能接入加密”。** 在已有私聊基础上覆盖群聊与成员变化、完整群历史分享、图片与文件、群话题接续、约定联系，以及授权端的搜索和导出。同机传输复用同一套内容与权限规则。范围与结束条件见[执行计划](secure-local-plan.md#3-完整社交功能接入加密)，新的想法不自动增加本批范围。

**部署状态：本轮尚未更新内网服务或日常安装版，也未迁移日常资料。** 未启用的窗口、旧历史、群聊和旧附件仍沿用明文路径。第三批完成后再按第四批备份、迁移和统一切换；安全审查、实际桌面操作及 Linux 通道验证仍需完成。原生桌面编译检查通过，原生单测启动错误仍未解决；干净 Windows、GNOME 与正式邮件等原有验收缺口继续保留。
