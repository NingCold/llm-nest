# 2026-09-12 第二轮修复

延续第一轮工作区修改。本轮集中于聊天中断的一致性和工具执行的协作式边界，未引入完整 Run/检查点架构。

## 行为变化

1. 取消、断流、provider 报错及消费端断开：先保存已收到的正文、思考链和取消/失败状态，再发终止事件。没有正文也保存空的中断消息，便于刷新后识别失败。保存失败会明确报错，内存不先行修改。
2. 中断回答仅用于历史展示，下一次发送请求时过滤，避免把半截输出当作模型已完成的答案。
3. 工具阶段中断时，对尚无结果的调用补充失败 ToolResult；已完成的调用不重复补写。与中断消息在同一次持久化事务中保存。
4. Web/Tauri 加载历史不再强制把所有消息标成 done；保留 error/cancelled 及错误内容。前端终止后重新读取真实历史。重新生成的预期消息数只统计持久化消息，排除临时错误占位。
5. Web SSE 转发等待上游期间也监听浏览器断开，及时取消请求。
6. Tool::run 必须显式实现非阻塞异步方法；注册表默认 30 秒超时，捕获 unwind panic，拒绝超过 64 KiB 的返回 JSON。原有 echo/add 继续可用。
7. 编辑消息索引统一只统计 GUI 显示的 User/Assistant/Tool，避免 Developer 消息影响定位。

## 兼容性

- 会话 JSON 新增可选 interruption 字段，旧文件默认正常完成；无需批量迁移。
- Tool trait 有源码级变化：自定义工具必须实现 run；仅实现 run_sync 不再足够。工具 crate 新增已存在于工作区的 tokio 依赖，Cargo.lock 未升级其他包。
- 保留开始本轮时已有的 CLI 和生成文件改动，不覆盖这些改动。

## 验证

- Rust：194 个测试通过（排除 Tauri 链接测试），本轮新增 7 个测试，覆盖中断保存、下次请求过滤、消费端断开、文件重载、写入失败回滚、工具超时释放以及异常/大输出。
- Web：类型检查与实际 TS hook/adapter 回归测试通过；增加历史状态透传检查。
- Tauri：cargo check 通过；尚未进行完整安装包/真实 WebView 验收。
- Vite 生产构建通过，仍有大包警告；输出在系统临时目录。cargo fmt --check 和 Clippy 通过（后者仍有风格警告）。
- 未调用真实收费模型 API。

## 尚未解决的边界

- 进程崩溃、断电或强制结束发生在收尾之前，仍可能丢失内存中的部分内容；需要 RunId、增量检查点和启动恢复。
- 超时是协作式的：不能强制杀死阻塞代码；输出限制不等于内存沙箱；已产生的外部副作用不能自动撤销。生产级文件/Shell 工具仍需进程隔离、授权及幂等设计。
- 多进程共用 JSON 存储的覆盖风险、持久化 MessageId、GUI 全量设置保存仍在后续列表中。
- 本轮的中断恢复是保留结果并允许重新生成，不是从执行断点自动续跑。
