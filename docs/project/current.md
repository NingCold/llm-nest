# 当前安排

[已完成](completed.md) · [待验收与候选](backlog.md) · [拆仓计划](repository-split-plan.md) · [使用指南](../usage.md)

**当前反馈：输入口令后解锁等待约 10 秒。** 已定位到锁屏会等待本机密钥库打开、服务器设备检查和完整密钥同步。源码已将已有可信设备的后续同步移到后台，保留进入前的设备有效性检查；新设备与未获信任的设备仍走完整流程。这次没有修改口令保护强度、身份或恢复材料。隔离测试不等于日常桌面的计时，安装版仍为 `alpha.15`，修复尚未打包安装，下一步是更新后测量实际解锁耗时。验证范围见[解锁等待优化](../validation/README.md#解锁等待优化)。

同步本身还存在已确认的重复工作：服务端每轮把全部活跃账号标为设备变化，官方 SDK 会对已跟踪账号再次查询公钥。本次仅核对代码并用临时身份验证该行为，尚未修改服务端；日常十秒的具体耗时分布仍待测，不归结为密钥数量过多。

连接器在服务端仓，但可以独立引用；现有 Agent 已使用它，不编译服务端，见[外部接入说明](https://github.com/NingCold/llm-nest-server/blob/main/connector/README.md)。用户已确认将第三方 Agent 接入 SDK 列为[未排期待办](backlog.md#未排期候选)，包括独立使用和发布、配对连接与任务处理，以及可运行的端到端加密接入示例；语言与首版范围实施前按需求确定。目前未实施 SDK，也未拆出新仓库。

**上一批已交付：桌面创建加密 AI 与节点额度。** 本地客户端 `alpha.15` 与 Agent `alpha.14` 已实现从创建、配置本机、配对、准备独立身份、保存或导入恢复文件、确认保管、双方核对信任，到保存初始角色模型、启动等待应用并打开私聊的完整界面流程，无需使用命令行准备本机 AI。已有身份走恢复，已有资料先读取；启动成功与资料应用分别确认。私聊仍需在聊天详情开启端到端加密。

停止 Agent 后可在同一界面修改节点每日调用次数与 token 额度，默认 48 / 1048576；本机同账号所有 AI 共享、按 UTC 日计算，调整不重置已用量。预留改为本轮输入估算加输出上限，结果未知不返还；不把预留值称为供应商账单。

本批已通过 Web 25 组测试、原生测试 32 项（另有 3 项忽略）、完整加密及历史迁移回归（使用模拟模型，真实 API 调用为 0）。共享界面的浅深色、网页/桌面与 390/800px 排版已检查。独立测试账号已在实际桌面完成可信设备恢复、本机配置和绑定、AI 首次身份、恢复文件取消后重开保存、保管确认、双方信任、停机保存首份角色模型、启动应用、运行中关闭再开设置、进入私聊启用加密及模拟回复。额度改为 17 次 / 123456 token，再改服务地址后额度和密钥引用保持，启动后的实际节点配置已核对。最终完整加密回归已使用安装包所用的 Agent `alpha.14` 通过（退出码 0），包括停止时直接保存首份角色模型；仅调用模拟模型，真实 API 调用为 0。历史迁移回归此前通过，真实 API 调用同为 0。

本地 `alpha.15` 已由 NSIS 安装（退出码 0），随包 Agent `alpha.14` 的版本和 SHA-256 已核对；升级前后 83 个日常持久文件逐项 SHA 保持。新安装版已启动并显示 Cold Nitrogen 账号的锁屏，保持登录成功；未解锁日常账号，本批没有使用真实 API 或发送日常消息。AI 恢复文件导入未单独进行 GUI 手测，恢复协议已有自动回归。详见[Windows 实际记录](../validation/windows.md#桌面创建加密-ai-与额度2026-11-01)。
