# 当前安排

[已完成](completed.md) · [待验收与候选](backlog.md) · [同机与加密计划](secure-local-plan.md) · [使用指南](../usage.md)

**第四批的功能、自动验证和版本更新已完成，正在进入日常资料切换。** 2026-10-24 已将内网服务、本机安装版和独立 Agent 更新到 `0.1.1-alpha.4`。用户确认尚未注册日常账号，现有记录来自此前验收。测试旧资料尚未批量转换，服务仍允许原有明文窗口使用，不能将版本更新等同于数据已经加密。

第三批“完整社交功能接入加密”已实现，完整自动回归通过。 群聊与历史分享、图片和文件、群话题接续、一次性约定联系都已接入原有加密协议。正文、文件名和附件解密信息由授权客户端与 Agent 读取；服务器保存密文，并继续管理成员、来源、任务和权限。

群成员变化后，按旧名单准备的新发送会被拒绝；新成员可以从有权成员或节点取得本群历史密钥。AI 退群后，它在该群的记忆、摘要和摘要设置失效，重入不自动恢复；管理员可以明确重新设置摘要。其他 AI 的资料不受影响。

同机私聊可携带加密附件和已准备的群来源，断云后继续使用本机 Agent 与可用模型，恢复联网只同步原消息、原附件和原结果。全文搜索和完整窗口导出在客户端分页读取并解密；缺少密钥或仍有未同步记录时会说明范围，不把缺失内容当作完整结果。

第二批提供的可信设备、恢复文件、离线资料修改与节点交接继续沿用。协议与权限规则见[加密契约](../design/crypto-contract.md)，使用方法见[使用指南](../usage.md)，实际测试范围见[验证记录](../validation/README.md#完整社交加密验证)。

本批新增“转换旧历史”：先备份和预览，再转换原窗口的消息、附件和已结束约定，保留原作者、顺序、读态与来源。转换完成前，从恢复文件独立读回所有记录、比对原内容；请求结果不明时可核对原回执或手动重试。节点资料有对应的预览与密文转换命令。专项验收和原有完整回归通过；转换过程不调用模型。

部署前已一致备份数据库、附件和本机节点，并将数据库还原到独立测试库核对。更新后服务健康检查通过，原有 189 条消息和 28 个窗口保留。本机 NSIS 覆盖安装成功，隔离启动已显示正常登录界面；MSI 已构建但未实装。独立 Agent 已更新，仍保持更新前的停止状态。Web 已实际检查窄窗口导航、转换状态和缺少密钥时的提示。

**下一步仍在第四批内：**

1. 使用已准备的单次邀请注册自己的账号，建立可信设备并保存恢复文件，再为 AI 准备加密身份与恢复材料；新账号可以直接开始加密聊天，不需要导入此前的测试记录。
2. 实际试用桌面同机、断网接续和换设备。若决定保留某些旧测试窗口或节点资料，再按[迁移指南](../migration.md#现有云端记录转为加密)转换并核对恢复；不会自动把旧测试账号或资料合并进新账号。
3. 完成安全审查及数据核对后，开启 `CLOUD_REQUIRE_ENCRYPTION`，正式拒绝新的明文内容。当前该开关为 `false`，尚未执行这一步。

旧明文备份及旧附件保留，清理另行确认。实际桌面加密操作、独立安全审查、Linux 通道及既有平台验收缺口仍见[待验收](backlog.md#待验收)；启动检查不代替这些验收。局域网直连、桌面重启后的离线重新登录和完整离线社交不属于本轮范围。
