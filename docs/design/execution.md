## 当前云端私聊与群聊执行

聊天提供显式启用 `sealedV1` 的执行路径：节点使用官方 Matrix SDK 解密材料，核验设备与账号 master 双签后复用原上下文与任务确认；流式、结果与中断片段只上传密文封装。资料须由当前绑定节点确认应用，换节点提供 drain/ready 握手；恢复不会自动重跑结果不明的调用。同机使用同一封装，Olm 密钥投递已通过真实 Windows IPC 验证，联调见[当前安排](../project/current.md)。群、附件与约定仍保留原权限和调度规则，内容由节点解密；完整协议见[加密契约](crypto-contract.md)。

`server/cloud` 与独立 `agent/node` 已实现云端 AI 私聊、群聊、有限自动接话和一次性约定；字段见[节点接口](api.md#云端-ai-与节点接口)，实际联调证据另由[验证记录](../validation/README.md)维护。协议为 v4，旧版本节点明确拒绝。云端不加载模型客户端，`llmn-agent` 复用 `ai-client` 与 `builtin-agent` 纯上下文核心，不依赖旧 Runtime/SocialStore。

云端先保存真人消息，再按结构化 mentions 顺序选出当前有效 AI，追加被回复 AI 并去重，为每个目标建立五分钟有效任务；群内普通文字名字不构成提及。默认没有明确目标不触发模型；开启有限自动接话后，普通真人输入和成功的 AI 回复可按额度继续轮转。私聊沿用对方 AI 触发，普通连续输入默认合并等待 800ms。一个触发消息以 aiResponses 数组记录各 AI 的任务状态，目标失败不把错误伪装成回答，也不覆盖其他 AI 任务。

材料传真实 conversation（kind/name/revision/当前 members），不以单个 peer 代表群。服务器选择触发位置以内原文，另允许本窗更早 queue_position 且状态 completed 的任务输出，其触发位置必须不晚于当前触发；对这些未撤回的 committed 消息取最近最多 100 条，不纳入后续无关真人输入，再补入必要触发消息及同窗 replyTo，即使它们早于最近历史；后一任务可以看到前序 AI 已提交的正文。节点按每个目标 AI 构造独立 ContextInput：仅该 AI 自己的正文可映射为 assistant，其他真人/AI 按 senderName 保留署名。图片预选及容量计算把触发和回复来源视为必要材料，超限明确报错；图片用任务授权接口读取，普通文件只附元信息。节点结合自己的显式记忆、窗口摘要和群原文引用生成上下文；仅实际使用的来源进入复核，接话、暂停、约定授权及自动次数由云端在开始和最终提交时复核。

每个节点进程可承载多个 AI，各自保持 WSS，共享四个社交调用槽和一个独立摘要槽；跨节点的群串行由云端持久 queue_position 控制。任务列表仅将每窗口队首 queued 或已有 running 交给相应节点，开始事务再次检查队首及每窗口最多一个 running。前一任务完成/取消后通知后续目标节点；不能靠各节点自己的并发限制保证整群顺序。

一次性约定以独立 contact 触发携带创建者、内容和到期时间，读取本窗口当前历史和该 AI 的记忆/摘要，不创建假消息，也不带入普通追问的隐式群引用。延期 contact 等待免打扰结束时，后续就绪任务可以先行；消息合并等待仍保持原有队列顺序。合并的所有 inputIds 都是必要材料，各条原文共同显示该次回复状态。

准备失败在调用前 reject，不生成虚构回答。节点严格解析模型与参数，以同一快照准备材料；按 UTC 日持久预留调用数及完整输入/输出容量，时钟回拨不重开旧日预算。开始前先把原 start 命令和预算写入本地 SQLite，命令携带 taskRevision、conversationRevision、完整 sources、derivedSources、materialScopes 和 configurationRevision；收到并保存云端持久确认后才调用模型。单次调用最长 120 秒，不自动重试模型。

仅当本次开始响应明确为 HTTP 409 `task_not_ready` 或 `conversation_busy` 时，服务器保证未开始；同一进程可在本地事务移除尚无回执的 intent 并撤销这一笔调用/token 预留，等轮到后重新读取准备材料。普通 409、网络失败和开始确认丢失均不能推定未开始；已开始调用的失败/取消不返还预算。该例外不使时钟回拨重开旧日额度，也不允许重启后猜测模型未执行。

开始事务复核当前绑定、AI 活跃状态、窗口 revision、成员/私聊屏蔽及实际读取的完整来源，将 sources 冻结保存。开始后读取材料、delta 和最终提交按冻结 ID/revision 逐条复核，不重新选取最近历史作为依赖；后来新消息不加入在飞快照。模型流每 500ms 至多提交一次累计正文检查点，最终结果先持久保存到节点再经 HTTPS 提交。云端最终事务提交消息、任务终态和事件；原结果只按原 ID/正文重交，回执重查当前权威状态，不复活已撤回正文。

群管理修改提升窗口 revision，保守取消该群所有未完成任务并清除失效派生片段；重新入群不恢复旧任务。源修订/撤回、节点替换/撤权沿用取消并清除失效派生片段的边界。真人停止、私聊屏蔽或 AI 停用保留来源仍有效的累计片段为 interrupted：屏蔽只影响对应私聊，停用只影响该 AI，其他群与其他 AI 正常执行；停用期间仍保存真人私聊消息，但不为停用 AI 排任务；恢复/解除只接受新消息。已提交历史不会因上述控制被删除。取消先在云端事务生效，再经 WSS 通知节点尽力停止，迟到结果不能覆盖终态。

节点失联会中断当前流，关闭聊天客户端不停止独立 Agent。节点重启先查询持久检查点对应的云端任务；已开始但结果不明按 uncertain 收尾，绝不再次打开模型流，本地已有 final 只按原 ID 和内容重交。服务端重启同样把旧 running 标 uncertain，保留有效片段，不重新排队。模型已经收到的调用可能仍产生费用，不能承诺回滚。

摘要任务由节点按 AI/窗口独立调度，使用独立摘要槽，与聊天共用节点整体持久预算。调用前先保存开始意图并取得云端持久确认；正文只在节点保存，云端只记来源、版本、状态与用量。重启将未完成摘要标为中断并补交终态，不再次调用模型；源变化或设置变更阻止旧结果写为可用摘要。详细分段和权限见[意识系统](consciousness.md#第-3-步第二批的接入方式)。

## 云端与节点的执行分工

在线角色/模型管理、资料迁移与执行使用同一独立节点边界；加密和同机路径遵守各自的开始确认与来源契约。

### 谁负责什么

云端 PostgreSQL 保存社交任务、发言资格、来源版本、开始确认、正式消息和持久事件；不加载 AiClient，不持有模型 Key。节点用本地 SQLite 保存 persona、模型绑定及参数、记忆、每个 AI 每个窗口的摘要、配置快照和执行检查点，自己调用模型。连接器传递中立任务、材料与结果，不要求外部 Agent 使用自带 Runtime 或意识算法。首轮社交仍不接入工具。

任务固定 taskId、AI/窗口、触发来源、必要输入、当前绑定版本和有效期。云端核验成员、屏蔽、账号状态、暂停、参与规则、约定授权与社交来源；节点核验模型能力、容量、预算和自己实际使用的记忆/摘要版本。平台不能独立证明外部 Agent 的内部模型调用数、费用或意识行为；节点报告的 usage 仅作报告，不作为已核实账单。

### 从任务到正式消息

1. 云端保存真人消息并产生有效社交任务；节点领取任务，通过 HTTPS 读取该 AI 有权使用且版本匹配的原文、图片和必要附件元信息。群其他 AI 的正文不能当作目标 AI 自己的 assistant 历史。
2. 节点固定模型目录/协议/参数、persona 和意识材料快照，检查本机并发与 token 预算。必要输入、显式引用和合并输入必须完整容纳，容量不足明确失败，不静默裁减或换模型。
3. 节点以原 taskId 与 requestId 请求开始，带绑定、任务和来源版本及本地快照标识。云端在事务内重新核验发言资格、有效期、来源和自动次数，持久保存开始确认。节点必须收到该确认后才可调用模型；确认丢失时查询同一开始请求，不能猜测已获准。
4. 节点保存本地开始检查点，调用冻结的 AiClient。临时 delta 只用于显示；草稿检查点与终态另行持久化。网络请求不跨云端或节点数据库事务持锁。
5. 节点完成后先保存可重交的原 ID 结果及本地快照校验结论，再提交云端。云端最终事务重新检查绑定、取消、成员/屏蔽、来源及参与授权，原子保存正式消息、任务终态、必要运行信息与持久事件，返回幂等回执；节点收到回执才标记已交付。节点内部记忆/摘要失效则中断依赖运行，不把旧结果提交为成功。

普通模型配置或 persona 修改只作用于新运行，已经开始的运行使用固定快照；节点更换、授权撤销、来源修订、成员退出和所用记忆遗忘属于撤销边界，不能被快照豁免。摘要归节点内部任务，按 AI/窗口独立组织，不形成云端发言、不共享给其他 AI、不占自动发言次数，但受节点模型预算。

### 断线、恢复与取消

| 持久状态 | 恢复行为 |
| --- | --- |
| 云端未记录开始 | 查询原开始命令确定状态；仍未开始且授权/来源/有效期成立时可以重新安排，未收到确认不可调用模型 |
| 云端已确认开始，模型结果不明 | 不自动重新调用；保留中断/结果不确定状态，不能因节点重启或确认丢失重做付费调用 |
| 节点已有完整结果，云端回执不明 | 按原 taskId/runId/messageId/requestId 查询或重交；当前取消、权限、来源和绑定仍可能导致拒收 |
| 已有云端终态 | 重试只读原回执及当前可见状态，迟到 delta/结果不能覆盖终态 |

进程仍持有同一次未调用模型的准备状态时，可以查询丢失的开始回执再继续；进程重启或丢失执行状态后，只要云端已记录开始，就按结果不确定收尾，不据“本机没看到结果”重新调用。云端生成 runId/messageId 并随开始回执返回，节点沿用这些 ID，领取任务时不另造正式回复。

云端取消或撤销先持久生效，拒绝旧任务/绑定的后续提交，再通知节点尽力停止。节点断线、供应商已接收或不可取消时，不能承诺立即停止、退还费用或回滚外部调用。节点不得为被拒收的结果新建消息 ID 绕过授权。客户端订阅断开只影响显示，不取消云端任务或独立节点。

## 模型参数与协议边界

模型名、provider、协议与思考强度由 Agent 严格校验，不替换不存在的模型。管理员保存的 temperature/max_tokens 属于该 AI 的档案；留空分别使用服务默认温度与意识系统输出预算，显式上限按原值预留并校验容量。节点使用同一配置快照解析模型、组装上下文和调用供应商，普通更新只影响新运行。

图片按精确 provider/model 的 supported/unsupported/unknown 能力检查完整请求，含历史及群引用；明确不支持时不调用模型，未知可以尝试，不按模型名猜测或静默丢图。图片能力声明不等于真实识图验收。供应商差异集中在 `agent/ai-client` 的协议适配器与共享 SSE 分帧，业务和客户端不构造供应商请求。

当前社交执行未开放工具、Shell 或任意文件操作；旧工具 worker 随宿主退役，不作为桌面或节点运行入口。模型输出不授予新权限，运行终态及已保存片段不能被迟到结果覆盖。
