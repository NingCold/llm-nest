# M2 第三批：群话题接续唯一私聊

[总纲](README.md) · [意识系统规则](03-consciousness.md) · [当前进度](in-progress.md)

日期：2026-10-13。本批打通群消息选择 → 引用草稿 → 唯一私聊发送 → 实际上下文读取 → 来源变化与权限撤销 → Web/IPC 更新。M2 三批至此完成，下一批进入 M3 参与节奏。

## 可体验的行为

- 群消息上的“私聊继续”选择当前共同 AI 成员及附近已加载的 1–8 条原文；可明确附带覆盖所选原文的一个有效群摘要。
- 打开原有唯一私聊，保留输入文字，加入可查看、可移除的引用草稿。导航不发送，刷新可恢复草稿，失败重试沿用同一请求 ID。
- 发送时引用随真人消息、计划和回执原子保存。来源卡展示群名、发送者、时间、序号及摘要范围；私聊内容不会回传源群。
- 新引用或显式回复旧引用时完整预留该话题；普通追问只延续最近 12 条 committed 私聊记录内最新的引用，并受剩余预算一半的上限约束。没有完整预算时，必要引用返回 budget_exhausted；普通附带背景跳过，不截断原文。
- 原文编辑/撤回、所选摘要任一原文变化、相关 AI 离群会使引用 stale，并停止依赖它的回复。重新入群或重建摘要不自动恢复旧引用，需要重新选择。

## 实现与边界

中立类型增加 ReferenceSelection，ContextReference 落在 SocialMessage 可选字段；SourceRef::Reference 固定关联私聊消息版本。目标 AI、窗口和发起者由服务端推导，客户端只选择来源。发送输入 reference=None 序列化省略，保留旧命令摘要；旧消息缺少字段仍可读取。

SQLite v9 的 context_references 按源群与目标 AI 索引关联消息，context_reference_sources 追踪所选原文及摘要覆盖的全部原文。正文仍保存在原群；消息、事件、草稿和回执不另存群正文。迁移前一致备份，不改写 v1–v8。

storage/social/reference.rs 负责来源预览、范围校验、上下文选材和失效传播。原编辑/撤回事务同步提高关联私聊消息/context 版本，更新依赖记忆/摘要并取消对应排队计划和在飞运行；失败会整体回滚。成员变更也使跨窗口依赖失效，Feature 随后停止已终结运行的模型消费。已经发布的私聊正文和原历史保留，不能把失效宣传为擦除全部既有回答或备份。

ConsciousnessService 以群来源 JSON 资料组织原文/摘要，使用当前私聊 AI 的执行绑定。ContextSnapshot 只登记实际读取的引用、消息、摘要和双方源群成员/上下文版本；开始与最终提交复核。仅有群成员身份不足以在快照中导入任意群消息，必须有有效的显式引用依据。

新增 POST /api/social/references/preview 与 social_reference_preview，其余沿用发送、消息读取和 message_changed 等事件。HTTP/Tauri 调同一 SocialFeature；React 的 LiveReference 提供选择器、草稿条与来源查看。预览只在在线且来源有效时展示，按游标重新读取，迟到响应不能恢复旧内容。失效引用的版本变化不再被误标成用户“已编辑”正文。

本批不实现自然语言群定位、语义自动召回、显式转发、自动提取或 Dreaming 式后台巩固。源群摘要必须显式选中，不自动触发额外模型调用；群记忆不会因此变成私聊关系记忆。安装与平台遗留验收继续暂缓。

全部使用独立临时数据和模拟 provider，未调用付费 API、访问个人聊天库或更新本机安装版。
