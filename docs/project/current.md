# 当前安排

[已完成](completed.md) · [待验收与候选](backlog.md) · [总计划](cloud-plan.md) · [使用指南](../usage.md)

**聊天加密规则 D1–D9 已全部确认，暂不实现。** [加密方案](../design/encryption.md)已同步确认结果、功能影响和建议实施顺序。当前讨论角色、记忆和摘要的云端密文同步，重点是离线修改、保存与应用的区别、遗忘、更换节点和恢复材料；新建议 S1–S5 尚未采纳，现有本地资料归属和在线管理行为仍有效。

已登录、已授权设备与同机本地模型 AI 的离线私聊已纳入待设计范围，尚未实现；当前继续讨论在线时是否也优先直连、如何同步云端，以及对离线授权、遗忘和换节点的影响。同局域网直连尚未确认，不扩展为完整离线社交。

**第 5 步“数据迁移与联网试用”的功能和隔离验收已完成。** 现在可以先备份、预览旧本地库，再把聊天、附件和个人列表状态迁入云端，把角色、记忆和摘要迁入对应 Agent。第一版使用命令行，操作方法见[迁移指南](../migration.md)。

本地真人对应当前登录账号，旧 AI 各自建立新的云端账号，同名不会合并。导入历史带来源标记，归档和旧导入窗口保持只读；所有迁入窗口先暂停接话，旧队列和约定不会自行执行。节点资料可以再迁往其他设备，重新授权后沿用同一云端 AI 身份；重复导入不会恢复已遗忘的记忆。

当前服务和 Web 已部署到授权内网。真实 PostgreSQL 的 37 项测试、Agent 与前端检查通过；独立旧库完成迁移、更换节点和网页检查，只有两次模拟模型调用。服务器备份恢复到临时数据库后，32 张表和 16 个附件一致；服务重启后的历史、节点重连和实时事件补齐也通过。详见[验证记录](../validation/README.md#数据迁移与联网试用验证)。

日常试用准备保留为后续安排：更新要使用的桌面客户端和 Agent，再选定实际需要迁移的旧库、查看预览并完成切换。当前先完成上述设计讨论；按用户要求暂不实施加密或同步改造，也不迁移日常资料。下一步继续确认 S1–S5 及同机离线私聊的通信与同步规则，实施仍等待用户安排；其他功能仍放在[候选清单](backlog.md)。

本轮只迁移合成测试库，没有迁移日常旧库、替换已安装桌面程序或日常 Agent。测试服务仍只在 Tailscale 内网使用；干净 Windows 安装、Linux 桌面和正式邮件等尚未验收的内容继续保留，不以本轮 Web 测试代替。
