# M1 共用界面现代化实现与验证

日期：2026-10-09。所属里程碑：M1，第 4 条业务线「双适配与阶段收尾」。本记录描述本批结果，当前视觉规范见 [界面与桌面](08-frontend-and-desktop.md#当前视觉与布局)，后续安排见 [正在推进](in-progress.md)。

## 实现范围

按用户选择采用中性灰白 / 炭黑与克制蓝色，重写共用社交主题与尺寸规则。聊天正文、输入、表单、列表和辅助文字形成明确字阶；桌面聊天与输入限制阅读宽度，手机采用列表 / 内容切换及底部导航，进入聊天后隐藏底部导航。消息、通讯录仍是两个主入口。

公开账号资料移除大封面，真人 / AI 仍使用同一资料结构。AI 管理页重排为横向角色选择、身份动作区与两列信息区，窄屏改为单列；长名称截断 / 换行与选中项定位已经处理。设置共用社交主题，手机分类横向排列，表单仍保留原挂载与保存行为。

消息列表提示各窗口草稿，生成气泡标注具体 AI，停止按钮明确该 AI 当前回复。补齐导航选中语义、中文关闭按钮和弹窗关闭后的焦点恢复；短动效响应减少动态效果偏好。实际角色切换检查发现管理员 / 账号运行区块使用相同 React key，已改成不同键，防止残留旧角色区块。

继续使用已有 React、Tailwind、Radix、Lucide 与 Markdown 渲染，没有增加依赖。领域、SQLite、HTTP/IPC DTO、权限、运行与草稿存储契约未调整；账号资料不展示内部设定，管理与只读账号查看仍走既有权限接口。预览共享样式与窄屏聊天布局，仍须显式启用。

## Antigravity 讨论

按用户指定的 consult-ai 技能咨询 `antigravity / gemini-3.8-flash-high`，完成设计建议与同会话复查两轮。采用中性主题、可读字阶、紧凑身份区及克制动效；复查后调整手机聊天导航、运行状态归属与多角色选择器。没有根据建议添加尚未实现的附件、搜索历史或重试按钮，也没有将发送操作替换成停止操作。

期间两次调用返回 `CLI_CONNECTION_ERROR`，均未自动重发；用户开启 TUN 并授权重试后，各次重试成功。MCP 将 EOF / 网络 / TLS / 连接诊断统一包装，不能据此确定具体网络原因。外部模型建议是设计参考，下面结果来自本地实际验证。

## 验证结果

使用独立临时数据、配置、WebView 目录与 loopback 模拟模型服务，没有读取个人聊天或调用应用配置中的真实厂商 API。

| 检查 | 结果 |
| --- | --- |
| `pnpm --dir frontends/web typecheck` | 通过 |
| `pnpm --dir frontends/web test` | 现有五组前端回归通过，包括公共资料 / 私有设定隔离、草稿、订阅与双适配 |
| `pnpm --dir frontends/web build:social-runtime` | 通过，产物仅在忽略的 `.social-runtime-dist`；仍有既有 Markdown / Mermaid 大 chunk 提示 |
| Windows MSVC Tauri CLI `build --debug --no-bundle` | 通过，嵌入共用前端，输出为调试 EXE |
| 实际 Web / HTTP | 浅深聊天、群成员详情、公开资料、管理与只读账号查看、设置往返、草稿保留、Escape 关闭与焦点返回通过 |
| 模拟慢回复 | 标注具体 AI，生成中继续输入且发送可用；停止后保留片段与下一条草稿 |
