# 存储与迁移

[总纲](overview.md) · [聊天与消息](conversations.md) · [API 与事件](api.md)

私聊和群聊可显式启用 sealedV1：新消息以密文封装保存，角色、模型、记忆和每 AI 摘要以分范围密文资源 CAS 同步；节点仍保存解密后的执行资料。设备公开密钥、Olm 信箱、恢复密文及版本元数据保存在云端，SDK 秘密与恢复解密材料不上传。旧未启用窗口和未转换历史仍保存明文。历史转换通过独立清单与指纹回执保留原记录标识，附件先写新密文目录再切换索引，旧附件留作受限备份；完成后 `crypto_history_complete` 不再允许旧位置明文。接口见[加密契约](crypto-contract.md)，联调见[当前安排](../project/current.md)。

## 当前云端存储

`server/cloud` 直接使用 PostgreSQL，不经过旧 SocialStore。`0001_accounts.sql` 保存 accounts、credentials、邀请、待验证注册、会话、密码重置和认证限流；`0002_chat.sql` 保存 cloud_contacts、cloud_conversations、cloud_list、cloud_messages、cloud_receipts、cloud_events。`0003_nodes.sql` 增加 AI 管理员、节点绑定、配对、任务及节点事件；`0004_groups.sql` 增加真实群与成员、结构化提及/回复、多 AI 任务回执、联系人屏蔽及账号启停。启动自动运行顺序迁移，不改写旧迁移。

双方 UUID 有序配对和唯一约束保证唯一私聊；群的 kind 为 group，first_id/second_id 均为 null，以 name 和 cloud_members 表达真实群，不使用 AI 账号占位。账号、窗口和消息 ID 均可沿用稳定 UUID。消息 position 是全局交付顺序，个人 read_position 不回退；消息发送、编辑/撤回、列表修改与相关账号的持久事件及回执在同一事务提交。写事务在分配事件 ID 前取得同一 advisory lock，保证可重放游标的提交顺序。init 和历史页的消息/读位置使用一致快照。

`cloud_members(conversation,account_id,role)` 是私聊与群的当前成员授权表，role 为 owner/admin/member；0004 为既有私聊补入双方 member。每群至多一位 owner 的部分唯一索引配合群管理事务保持群主不变量。成员变化提升窗口 revision，保留已提交聊天，取消未完成任务及其失效派生片段，并向旧成员和新成员提交事件；移出成员后每次读取均检查当前成员表。

0004 为 accounts 增加 status/status_revision，为 cloud_contacts 增加 listed/blocked/revision；通讯录列出与私聊屏蔽独立，移除联系人保留条目。cloud_messages 增加 sender_name（既有消息按发送者账号补齐）、reply_to、mentions UUID 数组与 ai_responses JSONB 数组；旧 ai_response 合并 aiId 迁为数组后删除旧列。历史署名不要求发送者仍是成员，mentions 保留明确选择的顺序，reply_to 由业务层复核同窗 committed 来源。ai_responses 按对应任务的 queue_position 重建，不将多个 AI 的状态覆盖成一个值。

cloud_node_tasks 新增 queue_position（唯一 bigserial）与 conversation_revision；窗口未完成任务的索引按 `(conversation,queue_position)` 支持跨节点 FIFO。材料选择限定于触发位置以内原文，另允许本窗更早 queue_position 的 completed 任务输出，且该任务的触发位置不得晚于当前触发；排除后续无关真人输入，最近 100 条之外仍补足必要触发/回复来源。开始事务复核队首、成员/账号/屏蔽、窗口 revision 与材料来源，持久保存 sources 后，后续 delta/result 逐条检查冻结来源，不重新选最近历史。`cloud_group_receipts` 按实际 owner/request 保存群与关系命令的 fingerprint 和窗口引用；不保存命令正文。AI 启停仍使用账号状态版本，取消只影响目标 AI 的未完成任务；屏蔽只影响对应私聊，二者保留有效片段为 interrupted，停用期间仍保存真人私聊消息但不为目标 AI 排任务，恢复/解除不重排。

附件元数据在消息 JSONB，原字节位于独立受管理目录的 `{messageId}/{attachmentIndex}`。先校验、独占创建文件、同步落盘，成功后提交数据库引用；数据库失败可能留下不可见的无引用文件，当前没有自动孤儿清理器。正文编辑保留原字节，撤回事务清空正文及元数据后删除文件。下载持有消息共享锁直至原字节读取完成；导出在一致快照中锁定完整消息及读取所选附件，避免撤回与读取拼出不一致记录。备份须配套保存数据库与附件，不将独立目录复制视为已实现的在线备份工具。

cloud_receipts 只保存命令 SHA256 与实体 ID，不重复保存正文或 base64；重复请求返回当前权威状态，旧回执不能恢复撤回内容。密码使用 Argon2 哈希，邀请、验证/重置链接、会话只存校验值和有效性信息。SMTP 秘密属于部署环境。云端保存 AI 社交任务、来源修订、开始/结果指纹与确认 ID、累计草稿及终态、用量报告和节点事件；配对/绑定只保存节点 secret 的哈希。云端没有模型 Key、persona、内部模型参数、记忆或摘要正文。

客户端草稿复用 IndexedDB，owner 包含服务器与实际账号，再按窗口隔离；文字、mentions/replyTo、附件 Blob 和不可变待确认发送命令同事务保存在本机，不是服务器正式历史。刷新不自动发送，未知发送结果只手动重试原 ID/原内容；首次明确拒绝才恢复可编辑草稿，已存在 pending 的后续权限拒绝不能证明旧发送未提交。浏览器来源隔离与桌面会话说明见[界面设计](frontend.md)。

[本地 payload 映射探针](../../server/cloud/tests/fixtures/README.md) 用合成数据和真实共享类型核对 UUID、公开资料、消息相对顺序及图片/文件原字节。旧 per-window sequence 需映射到云端 global position，旧正文 part index 需映射到云端附件索引。该探针只检查样本映射；第 5 步的正式迁移工具另外负责备份、预览、云端导入及节点资料包，范围见下文及[迁移指南](../migration.md)。

`0005_consciousness.sql` 在云端增加群话题引用及其来源索引、按稳定 AI 账号补齐的来源变更、节点材料版本和独立摘要调用确认。正式消息只保存 `context_reference` 的 ID、版本和失效标记，不复制群原文；摘要调用表只有来源、配置版本、状态和用量。在线管理请求与响应只经内存转发，不写入上述表或日志。

`0006_participation.sql` 增加云端窗口规则与状态、每日自动次数、一次性约定及其授权设置。社交任务区分消息和约定触发，保存合并输入、最早执行时间及规则版本。真人消息、任务与事件同事务；开始确认与自动次数同事务；成功结果、约定终态及后继接话同事务。约定命令回执只保存指纹和目标 ID，授权正文保存在意图记录中。

## 云端管理与桌面托管存储

`0007_management.sql` 为 accounts 增加 profile_revision、administrators_revision，分别保护公开资料与管理员名单修改；cloud_ai_bindings.capabilities 保存当前节点声明。在线档案正文不写入这些字段，能力声明不能代替当前在线连接与管理员授权复核。云端管理回执保存命令指纹和目标标识，重试返回当前结果。

节点 profile_receipts 按 AI/request 保存指纹。保存档案先检查同一操作者与原操作指纹、预期档案版本和完整模型参数，再在同一 SQLite 事务更新 profiles 与写入回执；回执不保存旧 persona 或模型参数，重复命令返回当前档案。

桌面目录位于默认数据目录的 `desktop-agents/<serverOriginSha256>/<humanUuid>`，由原生会话确定。desktop-config.json 原子保存配置及本机 Key 映射，node.toml 只使用环境引用，在配对和启动前从配置生成；现有 node.sqlite 保留。根目录 owners.json 仅登记服务器与真人账号，供退出及托盘查找已登记节点，不含登录凭据。desktop-agent.json 和 desktop-stop.json 是带实例 UUID 的原子状态/控制文件，不属于迁移资料；停止不信任持久 PID。该目录中的配置、凭据与秘密均不能打包、提交、上传 CI 或纳入业务导出。


## 当前节点存储

`agent/node` 独立使用 `node.sqlite`，与旧 `social.sqlite3` 无关。bindings 保存每 AI 的绑定版本和原始节点凭据，profiles 保存每 AI 的角色、模型选择和参数，tasks 保存开始意图、开始回执、草稿及原始最终提交，budget/meta 保存每日保守预留及不回退的日期。节点目录有独占进程锁和当前用户私有权限；凭据数据库不能提交、分享或打包。

节点的 `conscious_memory`、`conscious_summaries` 和 `conscious_settings` 按 AI/窗口保存记忆、摘要和设置；`conscious_scopes` 保存上下文版本，`conscious_cursors` 保存来源同步位置。写操作回执只存请求编号与指纹，读取不产生回执，避免轮询累积记录。遗忘或来源失效直接清空当前派生正文，回执中没有旧正文可复活。未完成摘要及其调用确认保存在节点，重启收尾而不重复调用。

`node.toml` 保存服务器、nodeId、CA 路径、预算与新绑定的档案模板，provider Key 只允许环境变量引用，解析出的模型 Key 不进入 SQLite。每 AI 档案由本机 profile CLI 或在线管理保存，角色与意识资料可以通过独立资料包迁往新节点。事务与恢复规则见[执行设计](execution.md#当前云端私聊与群聊执行)。只有同一进程收到云端开始接口明确 409 `task_not_ready`/`conversation_busy` 未开始响应时，才在本地事务删除尚无开始回执的 intent，并撤销该次预留的调用数/token，保留日期单调。普通冲突、断线、确认丢失、已开始或重启后的不确定状态均不适用该撤销路径。

节点的 `automatic_budget` 按 AI、窗口和 UTC 日记录自动调用的 token 容量，`model_reservations` 将预留与任务关联。开始意图、整体额度和自动额度在同一 SQLite 事务保存；仅当前进程取得明确未开始的队列冲突后，才一起撤销这次预留。已开始、确认丢失和重启后的不确定调用不退还。

## 同机文字私聊存储

`0009_direct.sql` 为 PostgreSQL 增加 `cloud_direct_grants`、`cloud_direct_receipts` 和 `cloud_direct_runs`。授权只保存 token 哈希，并绑定真人、AI、窗口、nodeId 与绑定版本；接纳回执只保存请求指纹和消息 ID，运行记录保存配置版本、用量与错误。已接纳正文仍进入原有 `cloud_messages`、来源索引和事件事务，不另建第二套云端聊天历史，也不为补传建立新的模型任务。

自带 Agent 的 `node.sqlite` 增加 `direct_windows` 和 `direct_turns`。前者保存获授权真人/AI/窗口、节点 grant、最近最多 64 条云端文字原文、末条 base、同步状态和错误；它是同机窗口的缓存，不代表完整历史。后者保存固定请求 ID、内容指纹、真人与 AI 消息 UUID/正文、排队与执行终态，以及实际使用的来源、材料版本、档案版本、用量和错误。以上内容保存在受限节点目录，没有加密或安全擦除承诺，不进入现有 AI 资料迁移包。

Send 先在 SQLite 事务保存真人消息和 queued 回合，再返回确认。模型调用使用共同的 `model_reservations`、节点整体次数/token 预算与并发槽；本机调用没有伪造的云端 start 确认。同一窗口的本机与云端执行共用串行控制。开始前持久记录 running 和执行材料，生成期间保存片段；停止或权限变化的中断状态不能被迟到结果覆盖。启动将遗留 running 标为 interrupted，不重复模型调用；尚未开始的 queued 可继续领取。

窗口同步状态分别为 pending、synced、conflict。每次只补传一个已结束回合；首次发送前把完整同步命令保存为 `direct_windows.sync_json`，网络结果不明时原样重试。确认后更新云端缓存和 head，并把该回合标为已同步；仍有后续本机回合时继续 pending。网络失败保留正文与待同步状态；当前权限、绑定、来源或云端历史不符则记录冲突并停止对应未完成回合，不丢弃本机记录或自动换节点。

桌面 IndexedDB 的待确认草稿快照增加可选 `route:"local"`，与 requestId、文字及附件快照一起保存，防止刷新后把未知本机发送改发云端。已选择的同机路线另以 localStorage 键按服务器、实际真人和窗口隔离保存；成功明确返回云端才移除。此标记不是授权，也不含登录令牌。当前桌面操作者由原生会话确定，退出、401、切服即清除内存身份；默认不持久保存会话，Windows 显式保持登录后用当前用户 DPAPI 保护令牌。重启仍先联网核对会话，再授权同机访问，不提供离线重新登录，详见[账号设计](accounts.md#登录会话与本机解锁)。

`run-managed` 在持有 `node.lock` 时清理旧 `direct-endpoint.json` 并创建新的私有通道；端点文件只含本机通道地址、实例 ID 和随机认证 token，普通 `run` 不创建。桌面原生层读取端点，不把 token、grant、模型 Key 或节点凭据交给网页。本机私有通道本身不等于端到端加密；第二批启用窗口使用相同的 sealedV1 封装与 Olm 密钥投递，已通过真实 Windows IPC 验证。不提供局域网连接。

## 迁移与备份

`0008_migration.sql` 增加 `cloud_imports` 的来源、内容指纹和 ID 映射，`cloud_messages.import_origin` 的历史来源标记，以及窗口 `read_only`。旧完成顺序与消息顺序可能不同，因此 `cloud_import_reads` 按账号保存迁移时已经读过的消息集合；后续新消息继续按正常读位置处理，不因位置转换把旧未读误标已读。

导入在同一事务新建身份、关系、窗口、消息、映射和通知，不走发送或任务入队流程。附件先在本批临时目录校验保存，再发布并提交数据库。提交结果不明时，等待原事务释放同一把锁后查询持久回执；确认未提交才清理本批文件，查询失败则保留文件等待确认。

本地迁移先取得旧目录锁，用 SQLite backup 生成完整备份，再生成仅含社交数据的上传文件。节点包根据持久映射改写来源。源库及旧迁移 SQL 不变；头像引用、旧审计与修订资料仍保留在完整备份中，当前迁移范围见[指南](../migration.md)。

节点 `transfer_receipts` 保存每 AI 的包 ID 和指纹。导入先同步来源、核对当前成员与消息版本，再原子保存新档案与材料版本，最后再次同步；同包重试不覆盖已编辑或遗忘的材料。未完成摘要作为中断资料，旧失效条目不恢复正文，自动摘要关闭。节点凭据、任务、预算、调用确认和同步游标不迁。

服务端备份需要 PostgreSQL 与附件配套。`cloud_restore_acceptance.py` 暂停指定测试服务取得快照，恢复到独立临时数据库和私有附件目录，逐表、逐文件核对后恢复服务，不覆盖原库。它是当前隔离部署的验收脚本，定期在线备份产品仍未提供。

## 云端与 Agent 的数据归属

[云端改造计划](../project/cloud-plan.md)确定了数据归属。真人/AI 私聊与群聊、成员与角色、屏蔽和 AI 启停、节点绑定/任务、节点意识资料、接话与约定、在线管理及命令行迁移均已接入。

### 数据归属

| 位置 | 权威数据与责任 |
| --- | --- |
| 云端 PostgreSQL | 真人/AI 账号、管理员、邀请与邮箱密码认证资料及会话、联系人与屏蔽、窗口成员与权限、消息与修订、附件元数据、已读置顶、事件和命令回执；节点绑定授权、发言规则、任务与执行终态 |
| 云端附件持久目录 | 经服务端校验的正式图片和文件字节；数据库记录附件 ID、所属消息与版本、格式、大小及完整性信息，不保存用户设备路径 |
| 自带 Agent 本地 SQLite | 按稳定 AI 账号保存角色设定、模型选择与生成参数、显式记忆、各 AI 各窗口的摘要配置/分段/来源版本、执行检查点；同机窗口另存近期缓存及未同步的本机消息，云端接纳后才成为云端正式历史 |
| 节点本机秘密配置 | 模型 Key 与连接秘密；独立节点 Key 从环境解析，桌面可将本机输入保存在私有配置并注入子进程环境；平台节点原始凭据保存在私有节点 SQLite；不写入业务导出、迁移资料包、云端存储或日志 |
| 客户端缓存与草稿 | 按服务器 + 实际登录账号 + 窗口隔离；缓存、附件草稿和待确认发送快照不作为正式聊天，也不因离线成为已发送消息 |

未启用加密时，云端不持久保存节点的角色设定、记忆、摘要正文和模型参数。在线管理请求经云端复核实际管理员授权后转发节点，已有关系/窗口显式记忆操作沿用成员与来源范围校验；节点提交本地存储成功才返回保存成功，离线时不排队修改这些资料。普通模型参数修改仅影响新运行，遗忘、来源撤销等操作仍使相关在飞运行失效。模型 Key 只在节点本机填写。外部 Agent 可自行选择存储，不强制使用 SQLite 或自带 Agent 的内部格式。

账号密码保存为密码哈希，邮箱验证、找回密码及节点连接凭据在服务端保存校验值与过期/撤销信息，原始秘密不写入日志或业务导出。云端自己的邮件服务凭据属于部署配置，与用户节点的模型凭据分开。

### 提交与备份边界

云端一次数据库事务提交消息/修订、来源依赖、正式附件元数据、任务变更、事件与回执；权限、屏蔽、任务及当前有效节点的复核与相应状态提交在同一事务内完成。领取任务和提交结果各自事务化，不跨模型请求持有事务。节点在本地事务中保存意识资料、来源版本、失效状态与检查点；两个数据库之间通过协议同步版本与状态，不假设跨库原子提交。云端复核社交来源和发言资格，节点复核内部资料版本。

附件先接收至服务端临时区域并完成格式、大小及完整性校验，再在同一受管理文件系统中持久写入正式位置，成功后才提交引用它的数据库事务。落盘失败不保存消息或成功回执；文件成功而数据库失败时留下未被引用的文件，由服务端清理，不向用户暴露为已发送。清理只处理已结束上传且无有效引用的字节，不能与尚在提交的事务竞争。消息修订/撤回先在事务中解除或更新引用，备份期间暂停清理。客户端只上传字节，不提供本机路径。

数据库与附件目录不构成分布式事务。备份采用短暂暂停写入和附件清理的维护窗口：排空正在提交的写入，取得 PostgreSQL 一致快照并复制该快照所引用的附件，记录配套备份标识及完整性清单后恢复写入。恢复必须成套使用数据库和附件，检查所有正式引用均有完整字节；不能把互不对应的数据库备份与目录复制声称为可恢复备份。节点意识资料另行备份，不包含本机秘密。

### 旧数据迁移与节点迁移

先备份旧库与附件并预览账号对应关系，再明确本地真人的云端身份、AI 身份及管理员；不得按同名自动合并。聊天、附件、关系与成员迁入云端，保留已读置顶、屏蔽和停用状态；角色、显式记忆及摘要迁入对应 AI 的节点。保存账号、窗口、消息和来源映射及导入记录，重复执行不产生重复实体。旧 SQLite 与顺序迁移保持不变、不删除；正式使用经过一次明确的单向切换，不长期双写。

旧私聊和群聊摘要仅在来源有效且目标 AI 仍有源访问权时，标明导入来源后作为该 AI 的初始摘要；此后各自维护。失效摘要不启用，无权读取的内容不分发，也不自动付费重新概括。旧未完成模型调用不重放，未来约定经预览后重新确认才启用，旧队列不因导入自动发言。

自带 Agent 换节点按 AI 导出/导入角色设定、模型参数、记忆、摘要及来源关联资料包，云端身份与聊天历史沿用；资料包不含模型 Key 或平台节点凭据，新节点重新配置并授权。导入检查目标 AI、ID/来源映射、版本和完整性；来源需按当前云端权限再核对。外部 Agent 自行适配资料迁移。资料包字段由 `connector::node::transfer` 定义，外部 Agent 无需采用这一内部格式。

迁移验收须证明：预览与实际导入范围一致；重复导入无重复消息/附件；附件完整性及来源映射可核对；权限不足的摘要未分发，失效内容未启用；旧库可独立保留并从配套备份恢复；新节点无旧秘密也能重新授权接续身份，旧调用和未经确认的约定不会执行。切换失败时保留旧库和导入记录供核对，不能自动把两边历史重新合并。

## 本机未发送草稿

客户端 `client/web/src/chat/draft-storage.ts` 使用 IndexedDB，以服务器、实际真人账号和窗口隔离文字、附件 Blob、结构化提及、回复和引用。发送前原子保存完整命令快照与 requestId；未知结果只允许手动重试原请求。成功后清理原快照并保留期间新增输入。恢复完成前不编辑，写入失败和多页面冲突明确显示，不覆盖另一页内容。

草稿默认本机明文，不属于 SDK 密钥库、服务端历史、跨端同步或整库备份。清理浏览器/WebView 资料会删除草稿。桌面关闭等待附件读取和 IndexedDB 事务确认；失败保留窗口。
