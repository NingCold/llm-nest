# 10 交付与验证

[总纲](README.md) · [当前开发指南](../development.md) · [当前约束](../../AGENTS.md)

状态：实施计划，所有里程碑尚未开始。本轮只交付设计文档。

## 1. 实施原则

按可运行的业务链路交付，类型、数据库、事件、两条 GUI backend 与界面在对应里程碑同步落地。完成某个 crate 编译不等于完成对应产品阶段。

遵守当前 Git 约定，保留未提交修改，不自动推送、创建 PR 或发布。大规模代码迁移如需隔离分支，实施前说明理由；设计文档本身不需要实验分支。

每次重构说明保留和改变的行为，同步修改当前规则，不能把“规划中”悄悄改写为“已经支持”。API、数据库和模型请求的实际契约以实现与验收共同确认。

## 2. M0：领域与持久化骨架

交付：新增 social 类型、共享事件 DTO、SocialStore 接口、SQLite schema、统一目录锁、只读旧格式导入器与 mock/fake clock 基础。

顺序：

1. 确认 ID、revision、sequence、状态枚举和依赖方向。
2. 验证 Rust SQLite 驱动在 Windows MSVC/Linux 的构建、备份、WAL 和错误处理。
3. 实现关键原子操作、命令回执与持久变更引用。
4. 实现 schema 迁移与旧 JSON 预览/导入，保持源数据不变。
5. 在独立临时目录验证锁、崩溃、幂等和失败注入。

完成条件：旧数据导入两次结果一致；损坏/冲突不静默修复；关键事务失败没有部分成功；已有窗口、配置和旧协议测试保持通过。M0 不宣称 GUI 已转型。

## 3. M1：身份与私聊、群聊

交付：SocialFeature 生命周期、联系人 CRUD、独立执行配置、私聊/群聊/成员、消息发送和修订、@队列、取消/暂停/结束，以及新 GUI 和双 backend。

先完成确定性 mentioned_only，不引入自动相关性接话。建立持续订阅和游标补齐，发送不再预建回答；AI 生成时允许真人继续发送。

第一条可体验链路：创建 AI → 创建私聊/群聊 → 保存真人消息 → @选择 AI → 固定上下文 → 模拟 provider 流式生成 → 原子完成 → 重连读历史。

完成条件：一个真人与三个 AI 的身份和发言清楚，@多个 AI 顺序可控；输入连续保存；修改早期消息保留后续历史；暂停与完成竞争不发布停止后的成功；HTTP/IPC 契约一致。

M1 同步修订 README、AGENTS 的当前定位、代码地图和无模型发送规则。新业务未完成前保持现有规则，不能提前据规划修改运行事实。

## 4. M2：关系记忆与上下文

交付：简单显式记忆条目、关系/群范围、来源版本、聊天摘要、按 ActorId + ConversationId 构造的上下文预算、遗忘标记，以及聊天详情和联系人详情中的记忆面板。

先实现手动添加/编辑/遗忘与权限筛选，自动候选提取和复杂后台巩固不作为 M2 完成前置。摘要生成及未来记忆提取使用明确的模型绑定和独立预算，不能暗中调用另一付费模型。后续加入提取时同时实现候选确认和已知来源遗忘抑制。

完成条件：完整窗口记录持续保留；近期上下文由软件构造且各空间隔离；摘要可追溯并接续较早话题；模型更换后记忆归属正确；私聊记忆和新成员不可见历史不进入群请求；编辑/撤回/遗忘使派生内容失效。

## 5. M3：节奏与约定联系

交付：连续输入合并、limited_auto、Bout 等待/空闲结束、轮数/预算限制、一次性 ContactIntent、免打扰、过期与崩溃恢复。

优先由确定性规则实现等待和上限，再验证模型建议是否改善时机。默认主动联系关闭，先支持用户创建的一次性约定；多 AI 自动交谈有限且可随时停止。

完成条件：fake clock 下复现到期、过期、免打扰和时钟变化；退出后不调用模型；重启不重复发布或重放不确定副作用；过期计划不集中补发。实际体验确认初始延迟与自动轮数参数。

## 6. 首版完成后的兼容收尾

梳理旧 ChatFeature、SessionManager、旧 HTTP/chat-event、demo 和 CLI/TUI 依赖。终端兼容转入同一用例后，逐步去除重复业务；保留必要旧格式读取与可验证导入。

更新 acceptance 脚本和 CI，移除失效断言，保留配置、协议、worker、平台与发布基线。不得通过删除失败测试掩盖持久化或中断回归。

## 7. 验证层次与命令

| 层次 | 主要验证 | 能证明什么 |
| --- | --- | --- |
| 领域 | 身份、成员范围、状态转移、有限参与 | 确定性规则 |
| 存储 | 事务失败、锁、幂等、迁移、杀进程 | 本地持久化与恢复 |
| 执行 | 模拟 provider 的工具/流式/错误/快照 | 模型调用组织与收尾 |
| 传输 | 真实 HTTP 与 IPC DTO 对照、回放/溢出 | 两条适配契约 |
| GUI | 输入保留、状态、重连、暂停、记忆 | 产品交互 |
| 包与平台 | Tauri 构建、实际安装、worker、窗口 | 目标环境与产物 |
| 真实 API | 已授权的付费协议与体验检查 | 指定模型和当时服务行为 |

首版新增包后，按受影响范围运行以下命令；包名为目标名称，当前仓库尚无 social/social-feature：

```bash
cargo fmt --all -- --check
cargo test -p social -p social-feature -p storage -p runtime -p events --locked
cargo clippy -p social -p social-feature -p storage -p runtime -p events --all-targets --locked
pnpm --dir frontends/web typecheck
pnpm --dir frontends/web test
cargo build -p web-server --locked
python scripts/acceptance.py
```

影响 ai-client、工具或旧 chat 时补跑对应包。完整里程碑按范围执行 `cargo test --workspace --locked` 与 Tauri 打包；Linux 开发依赖按开发指南准备。真实 provider 不进入默认离线验收，只有明确授权后使用。

## 8. 必须覆盖的端到端场景

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 同模型创建三个 AI，重复打开私聊 | 身份互不混淆，每个角色私聊唯一，各群独立 |
| A02 | 生成中连续发送 | 消息不丢失，顺序稳定，后续计划有限 |
| A03 | 编辑早期消息 | 后续历史保留，旧来源派生内容失效 |
| A04 | 私聊记忆与群提问相似 | provider 请求中仍无未授权记忆 |
| A05 | 新 AI 入群 | 不通过历史或摘要看到未共享内容 |
| A06 | 暂停与成功提交竞争 | 停止事务生效后不再发布成功回答 |
| A07 | SSE/IPC 断线与重连 | 无漏消息和重复发布，终态覆盖 delta |
| A08 | 到期计划前进程崩溃 | 安全待办重新评估，已 dispatch 不自动重放 |
| A09 | 工具执行中退出 | 子进程终止，草稿与失败配对可恢复 |
| A10 | 磁盘满/事务失败 | 无伪成功或内存部分更新 |
| A11 | 旧数据重复导入 | 计数、UUID 与来源映射稳定，原文件不变 |
| A12 | 目录冲突和迁移失败 | 锁不降级，错误带实际路径 |
| A13 | 更换模型或热更新 | 身份不变，在飞路由来自同一快照 |
| A14 | 自动 AI 互相触发 | 达到轮数/预算上限后停止 |
| A15 | 遗忘后回放，后续加入自动提取 | 事件不带旧原文，已知来源不恢复条目 |
| A16 | Web/Windows/Linux | IPC、窗口、路径与安装标识基线保持 |
| A17 | 同 AI 私聊与多个群，生成摘要 | 请求上下文按空间隔离，原记录完整保留 |
| A18 | 消息/通讯录与两种详情切换 | 无记忆主导航，关系记忆一致，群记忆归属明确 |

测试使用合成档案、临时数据和模拟 provider，禁止复制真实个人会话或配置到 fixture、CI 或发布资源。测试应检查结果和边界，避免只镜像实现。

## 9. 后续多人阶段

需要单独设计账号与 Actor 的控制关系、邀请与成员授权、云端存储、消息同步冲突、离线推送、滥用治理和服务费用。首版稳定 ID 与事件契约提供扩展起点，不意味着这些功能已经实现或可以无成本接入。
