# 消息列表与正文搜索

日期：2026-10-13。当前规则见[聊天与消息](02-conversations-and-messages.md)、[存储](06-storage-and-migration.md)、[接口](07-api-and-events.md)和[界面](08-frontend-and-desktop.md)。

本批完成日常消息列表：未读提醒和筛选、手动已读/未读、置顶，以及完整正文搜索和原消息定位。Web 和 Tauri 使用同一 SocialFeature 与 SQLite；没有添加独立模拟存储或旧入口。

## 使用行为

- 列表数字表示尚未读到的他人消息，手动未读用蓝点提醒。自己的消息、生成中消息和撤回消息不计数；保存下来的中断回复计一次。
- 在聊天中阅读最新消息，页面可见、有焦点且滚动到底部时，读取成功后确认已读。翻历史、看搜索结果、切到其他页面或窗口失焦都不确认。
- 当前聊天手动标为未读后返回列表，避免刚设置的提醒被自动清掉。下次打开最新聊天时再确认。菜单同时提供置顶与取消置顶，Escape 可关闭。
- 置顶优先，同组按最近消息完成顺序排列。已读和置顶保留到下一次打开应用；归档窗口和导入历史也能整理、搜索。
- 搜索框同时匹配聊天名字/成员与完整正文，可限定当前聊天。中文、emoji 和符号按字面查找，ASCII 英文不区分大小写；每页 50 条，可继续加载与重试。
- 点击结果进入原窗口，突出显示目标及前后各最多 50 条记录；“返回最新消息”恢复普通聊天。

## 保存与并发

SQLite v12 增加 `message_deliveries` 和 `conversation_list_state`，移除原来没有正式用例的 `read_positions`。迁移前按既有机制备份，旧迁移不改写，原消息和引用保持不变。迁移时已有历史及随后显式导入的历史初始化为已读；尚在生成的消息完成或恢复中断后仍提示未读。

消息的聊天顺序在开始生成时分配，完成顺序在首次进入 committed/interrupted 时同事务分配。读位置使用后者，因此先开始但后完成的回复不会漏计。编辑不会再次分配完成顺序；撤回后不再计数，也搜不到旧正文。

列表写入使用实际账号与窗口权限、独立版本、命令回执和 `conversation_list_changed` 引用事件。读位置单调并校验所属窗口。个人操作不改空间、意识、参与或模型配置，不中断 AI。管理员只读查看不会替另一个账号确认已读。

搜索直接读取当前原文，不维护额外正文副本。按当前成员关系过滤，并按完成顺序分页，不依赖已加载的 200 条历史；不查询草稿、旧修订、思考详情或角色内部设定。新查询、来源变更和页面离开使迟到读取失效。当前是本地字面子串检索，语义搜索、附件检索和大型全文索引属于后续扩展。
