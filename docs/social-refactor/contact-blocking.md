# 联系人屏蔽

[身份与关系](01-identity-and-relationships.md) · [API 与事件](07-api-and-events.md) · [进度](in-progress.md)

本批属于 M0–M3 核心完成后的日常社交体验，使用新版唯一运行架构。规则与实现于 2026-10-13 整理。

## 使用规则

| 场景 | 屏蔽后的行为 |
| --- | --- |
| 私聊 | 保留原窗口、历史和草稿，拒绝双方的新消息；停止正在生成和排队的回复，已保存片段标为中断 |
| 共同群 | 不退群、不隐藏任何成员的消息；完整历史、@、回复和已授权的自动接话照常 |
| 约定联系 | 取消屏蔽双方之间待完成的约定，包括共同群中由本人创建的约定；停止相关正在执行的约定，不能新建 |
| 解除屏蔽 | 沿用原私聊，只响应新消息；已取消的回复和约定不恢复，需要重新约定 |
| 移除、重新添加联系人 | 只改通讯录是否列出，保留屏蔽状态；未列出的账号也可以屏蔽和解除 |
| 账号与数据 | 不改账号状态、管理员权限、模型或群成员，不清空记忆、摘要和原文，不重置已读与置顶 |

这是双方之间的个人关系操作。共同群中其他账号的约定不受影响；管理员停用则是账号级操作，停止该 AI 在所有窗口的运行。旧记录仍可阅读和搜索，原有记忆管理、自己的消息编辑/撤回入口保留。屏蔽不等于遗忘，也不撤回已经发送给模型服务的内容。

## 实现

`ContactEntry` 增加 `blocked`，与 `listed` 共用联系人条目版本，两种修改分别提交，互不覆盖。SQLite v13 在 `address_book` 增加默认 false 的列；旧迁移保持原样，升级前备份。联系人尚无条目时，屏蔽创建 `listed=false` 的条目。

`set_contact_block` 在一个事务里保存关系状态、取消相关私聊运行/计划与约定、结束私聊当前交谈，并记录事件和命令回执。失败完整回滚。重试同一命令返回当前状态，不重新执行旧屏蔽；修改过的请求内容不能复用请求 ID。屏蔽/解除提升已存在 Relationship 的版本，阻止屏蔽前准备的上下文在解除后迟到启动。

发送和底层追加消息检查私聊关系；运行开始及成功提交复核关系，约定创建、到期入队、准备和提交复核屏蔽。任一方向的屏蔽都限制私聊和双方约定，普通群聊不检查这个限制。SocialFeature 在事务结束后取消已终止的模型任务，并继续调度仍有效的其他计划。

HTTP `POST /api/social/contacts/{id}/block` 与 IPC `social_set_contact_block` 调用同一用例。输入为 `requestId`、`blocked`、`expectedRevision`（不存在条目为 null），返回当前 ContactEntry。实际操作者由宿主确定。沿用 `contact_changed` 事件；Conversation DTO 的 `directBlocked` 表达该窗口的有效双向屏蔽状态。

共用界面在联系人资料、私聊详情提供屏蔽与解除。首次屏蔽先展示影响并确认；失败保留操作和重试 ID，成功后刷新。私聊显示屏蔽提示，保留草稿；群约定表单排除已屏蔽对象。通讯录保留列出状态，并显示“已屏蔽”，未列出的账号可在“本地账号”找到。
