日期：2026-10-13

[总纲](overview.md) · [聊天与消息](02-conversations-and-messages.md) · [共享接口](07-api-and-events.md) · [实施顺序](TODO.md)

本批打通文件选择、草稿保存、消息发送、历史显示和单文件下载。Web 与 Tauri 共用业务与 React 界面；普通文件与图片消息分别展示。模型暂不读取普通文件内容，文档解析另行安排。

## 使用与限制

输入框新增“添加文件”，可以选择文档、文本、压缩包等文件；发送前显示文件名、大小并允许移除，支持只发文件，也支持同时附带文字或图片。拖放或粘贴中的图片继续走图片流程，其他文件进入文件草稿；明确通过“添加文件”选择图片时，保存为普通文件，不开启识图。

每条消息最多 4 个普通文件，单个不超过 10 MiB、合计不超过 20 MiB；零字节文件允许保存。图片仍遵守原来的 4 张、单张 4 MiB、合计 8 MiB 和尺寸限制。文件名必须是普通名称，最多 240 个 UTF-8 字节，不能包含路径、控制字符、Windows 不可用字符或保留名，也不能以空格或点结束。浏览器未提供类型时使用 application/octet-stream。文件只按字节保存，不解压、不执行、不在页面中展开 HTML 或脚本。

文件草稿与图片共用 IndexedDB 的同一完整命令事务，保存 Blob、名称、类型及大小。刷新或重新打开同一入口可恢复；发送结果未知时只允许手动重试相同内容和 requestId。成功回执只清理已发送的文件，保留等待期间新增的输入。桌面关闭等待整个附件读取与草稿写入，失败保持原提示与重试入口。旧图片草稿没有 files 字段仍可恢复，无需升级 IndexedDB 结构。

混合选择时先检查图片能否进入既有流程；需要压缩的图片进入确认窗口，普通文件可先保存在草稿里，图片确认后才加入。取消图片处理不会删除已加入的普通文件。

## 存储、访问与模型上下文

SocialContent::File 增加可选 name，旧数据缺失时保持 None，序列化继续省略该字段。旧附件显示为 attachment.bin，原数据不改写。文件与真人消息、事件引用及命令回执一起写入 SQLite；数据库仍为 v13，没有重写迁移或新增存储目录。正文修订保留附件并更新索引/版本；撤回清空附件与旧修订正文，历史下载地址立即失效。

普通历史 DTO 只包含 index/name/mime/byteLength，不返回文件字节。单文件保存重新读取消息，复核当前成员身份、part 索引、消息版本和撤回状态；管理员只读账号视角同时复核管理员与目标账号成员身份。桌面路径来自系统保存对话框，选择后重新读取和复核，再用同目录临时文件写完、同步并替换；取消不创建文件，保存失败不显示成功。

意识系统、群话题引用和窗口摘要仅使用文件名称、类型、大小及“文件内容尚未读取”说明，不把文件二进制交给模型，不生成空协议块，也不估造文件正文。图片能力检查只检查真正的图片 part，普通文件声明 image/* 类型仍作为未解析文件处理。文件占位按文本预算计算，原始文件大小不会消耗模型文本预算。

聊天 Markdown/JSON 导出记录文件名、类型和大小。当前“包含图片”ZIP 仍只附带图片，普通文件需要逐个保存；文件打包导出是下一批建议。正文搜索仍查消息正文，文件名/内容检索不在本批范围。

## 共享契约

| 内容 | 契约 |
| --- | --- |
| 发送 | 现有 social_send / POST messages 增加可省略 files 数组，元素为 `{name,mime,data}`，data 是无前缀 base64 |
| 历史 | Message.files 为 `{index,name,mime,byteLength}[]`；index 是完整 body 的 part 索引，撤回为空 |
| 普通下载 | `GET /api/social/messages/{id}/files/{index}/download?revision=...` |
| 账号视角下载 | `GET /api/social/ai-accounts/{account}/view/messages/{id}/files/{index}/download?revision=...` |
| 桌面保存 | `social_save_file({id,index,revision,account})`，返回 cancelled 或 saved/fileName |
| Web 保存结果 | downloaded/fileName，只表示浏览器已开始下载 |

HTTP 下载统一 application/octet-stream、Content-Disposition: attachment、UTF-8 文件名、no-store 和 nosniff。仅发送消息路由的 JSON 上限为 40 MiB，覆盖图片和文件合计 28 MiB 的 base64；服务端分别执行图片和文件限制。存储按原始附件字节加文字限制消息大小，不把 JSON 数组膨胀误算成上传大小。读取和下载不改已读、事件或运行。
