# 同机聊天与加密执行计划

[当前安排](current.md) · [设计规则](../design/encryption.md) · [云端第 0–5 步](cloud-plan.md)

这份计划接续已经完成的云端改造。用户已要求开始实施同机直连，将局域网直连记入待办；后续按下面四个可体验的结果推进。设计细节集中在[加密方案](../design/encryption.md)，本文件只维护执行顺序和完成条件。

## 执行依据

- 聊天加密采用 D1–D9：客户端和 AI 节点解密，平台保存密文及必要元数据；保留独立账号、唯一私聊、完整群历史和可信 AI 管理员。密钥恢复独立于账号密码。
- 角色、模型参数、显式记忆与每个 AI 自己的窗口摘要按 S1–S5 作为同步设计基线：密文存云端，节点保留工作副本；保存、同步、应用分别显示；冲突不覆盖、遗忘不被旧备份恢复，换节点保留账号和历史。模型 Key 与设备凭据留在节点。
- 同机私聊优先直连。已授权的桌面客户端可以在断网时与同机 Agent 和本地模型聊天；联网后同步已有记录，不重新生成。离线节点不能即时获知远端撤销，重连时先核对再决定能否接纳记录。
- 同机与云端采用同一账号、窗口和消息标识。继续使用独立 Agent 和连接器，不恢复旧产品入口，不把本机 Runtime 作为云端失联时的替代产品。
- 局域网直连、浏览器完整离线运行、离线群聊和公网点对点连接不进入这轮完成条件。

## 1. 桌面同机文字私聊与断网接续

**状态：已实现，自动验证通过；日常安装版已验证同机文字私聊、断云接续及自动补传，Linux 实机仍暂缓。** 在已安装的 `alpha.5` 中，联网和断云各完成一轮真实回复，重连后没有重复调用或新增云端任务；模型互联网连接保留，未验证全网断开、本地模型或重启。具体证据见[Windows 记录](../validation/windows.md#日常同机私聊与断云接续2026-10-25)，原自动验证见[验证记录](../validation/README.md#同机文字私聊验证)。

第一批完成时使用原有账号登录、节点凭据和云端明文存储。第二批在同一条路径增加消息密文和加密密钥包；不能把第一批的验证单独当成加密验证。本机通道仅供同一操作系统用户访问，不开放局域网端口。

首批范围为普通文字，以及节点已有角色、显式记忆和摘要。附件、回复引用及群话题接续继续走原云端流程；准备本机上下文时遇到本批不能处理的材料要明确提示。缓存只覆盖近期历史时说明范围，不把缓存称为完整历史。已有登录会话可以断网继续使用；桌面进程重启后的离线解锁不在本批范围，重新登录后可以读回节点保留的对话。

完成条件：

- 原消息界面能够明确开启同机聊天，区分本机已保存、云端待同步、同步成功及冲突；退出账号或切换服务器后不能继续操作旧账号的本机聊天。
- 本机 Agent 独立后台运行，连接仅走私有本机通道；普通用户输入不能指定任意数据目录、操作者或模型凭据。
- 断云后模拟模型能继续回复，同一请求重试不重复调用；停止、崩溃和生成结果未知均保留状态，不自动重做。
- 云端只接纳当前授权、绑定和来源仍有效的本机记录；已有云端新消息、暂停、屏蔽或绑定变化造成的冲突保留本机记录并显示原因，不覆盖云端。
- 补传不会创建第二次 AI 任务；原云端私聊、群聊和节点任务继续正常工作。用独立数据和模拟模型验证，不迁移日常资料。

## 2. 私聊、设备恢复与 AI 资料加密

**状态：已实现并通过完整自动验收；日常真人和 AI 的密钥准备、双向信任、加密私聊及第二台网页设备恢复已验证。** [协议选型与接入约定](../design/crypto-contract.md)采用 Matrix 官方 SDK、账号与设备双签、可信设备及独立恢复文件。

选定适用于本项目的成熟加密实现，打通真人可信设备、AI 节点、私聊及管理内容的端到端加密。同步角色、模型参数、显式记忆和窗口摘要；节点离线也能保存密文配置，客户端断网可保留待同步修改。建立 AI 恢复材料，正常换节点与旧节点损坏时都能恢复已同步内容。

自动验证覆盖真实官方 SDK、独立云端与 Agent、Windows 私有 IPC、离线资料应用、摘要生成与来源失效，以及新节点恢复；见[验证记录](../validation/README.md#私聊与-ai-资料加密验证)。日常同机断云补传、新网页设备恢复和补强回归已完成；本轮第四批内网日常恢复收尾结束，桌面云端、同机与 Edge 均逐条读回原文。公开发布前独立审查仍保留，修复后的真实客户端重启验读不以 SDK 重开回归代替。

完成条件：平台不接触这些内容的明文；换设备需要可信授权或恢复材料；保存与应用区分清楚；本机与云端传输使用相同加密内容，断线补传不会生成新消息或新调用。新增、编辑、遗忘及来源失效在在线和离线情形下均符合设计规则。

## 3. 完整社交功能接入加密

**状态：已实现，完整自动回归通过，已随第四批更新版本；日常旧资料尚未转换。** 覆盖群聊和成员变化、完整群历史分享、图片与文件、群话题接续、约定联系、搜索和导出，复用第二批已经保护的流式回复。搜索与可读导出在授权客户端完成，同机直连使用相同的密文附件与已准备的来源。具体证据见[验证记录](../validation/README.md#完整社交加密验证)。

群历史只分享给当前有权成员，按旧成员版本准备的发送不能成为新消息。AI 失去群访问权后，其群记忆、摘要及设置留下失效记录，重入不自动恢复；摘要设置需要明确重新保存。同机补传仍核对绑定、来源和窗口状态，不重新排模型任务。

完成条件：当前社交首版功能均能在加密环境使用；群权限和管理员权限没有扩大；旧设备撤销后不能取得后续密钥；本机、云端、重连及多设备不会造成重复消息、错误回复关系或被遗忘资料恢复。

## 4. 存量切换与日常试用

**状态：本轮第四批 Tailscale 内网日常试用切换与恢复收尾已完成，转入日常试用和反馈。** `alpha.9` 回归、部署与 NSIS 实装完成，强制加密已启用；双方显式恢复授权后，桌面云端、桌面同机与 Edge 的十个原 ID 和全部正文均逐条读回，密文、备份、身份和调用次数核对通过。未新建身份或增加调用，旧测试资料原样保留，不转换、删除或迁入日常账号。修复后真实客户端重启验读尚未执行，SDK 独立重开回归已通过；其他平台及公开发布前的独立审查继续见[当前安排](current.md)。

需要转换的旧聊天、附件和节点资料，在备份和预览后由授权端迁入加密格式；本轮选择保留旧测试资料，日常账号从新窗口起使用密文。新版本服务已拒绝新明文，不自动改写旧历史、附件或备份；实际删除仍须另行确认。

本轮内网试用结束条件为：已完成代码检查和自动回归、备份与恢复核对、实际客户端设备试用，并在授权内网更新后拒绝新明文；这些结果现已完成。公开发布前仍需独立安全审查及相应平台验收，不能把内网试用切换称为生产或全面安全验收。未具备的 Windows/Linux 环境继续按原安排保留验证缺口。

## 日常使用补充：保持登录与本机锁屏

在已完成的四批能力上补充日常进入与锁定流程，不新增社交或加密协议阶段。用户可分别选择 30 天保持登录及 30 天自动解锁，两项均默认关闭；Windows 使用当前用户 DPAPI，Web 使用当前浏览器内的封装材料，非 Windows 原生端暂不支持。新设备仍需可信授权或恢复文件，不由登录成功取得密钥。

已有本机设备未解锁时，独立锁屏代替聊天组件，保留账号和导航位置，恢复入口独立可达。手动锁定先保存草稿，再关闭 SDK 并卸载聊天及订阅，Agent 继续运行；自动解锁暂停跨刷新及重启保留，成功手动解锁后恢复。退出清理自动材料，不删除原 SDK 库。登录会话与自动材料分别绝对到期，不能由使用滑动续期，也不将本机材料的应用到期称为密码学失效。

完成条件为：默认选项、到期、手动暂停、退出清理、会话隔离、失败与迟到结果均经隔离验证，锁屏不残留聊天 DOM 或订阅，原恢复与身份连续性保持；源码验证、真实客户端重启和部署安装分别记录。本批源码、隔离验证、`alpha.10` 内网部署和 Windows 覆盖安装已完成。未登录启动与重连已检查，真实账号重启及自动解锁待试用，见[当前安排](current.md)。本批不包含生物识别、WebAuthn 或离线重新登录。

## 待办与范围控制

局域网直连放入[待办](backlog.md)：在设备明确配对后复用同机聊天的消息、授权与同步规则，届时再处理地址变化和连接方式。它不阻塞这四步，也不自动升级成公网点对点网络。

每一步都包含实现、必要验证和文档更新。完成情况只写入[当前安排](current.md)与[已完成](completed.md)；测试数量、安装和部署状态按实际结果填写。新的想法进入候选清单，不拆成无止境的小阶段。
