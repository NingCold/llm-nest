# 08 界面与桌面

[总纲](README.md) · [API 与事件](07-api-and-events.md) · [运行时与配置](09-runtime-and-configuration.md)

以下编号章节描述完整目标；前面的真实 Web 与预览分别说明当前行为。 实施状态见 [已完成](completed.md) / [尚未完成](pending.md)，当前调用契约见 [API 与事件](07-api-and-events.md)。

## 当前真实 Web

普通 Web 开发和生产入口使用 `social/App.tsx`，通过 HTTP 读取 SQLite 的联系人、独立绑定、唯一私聊、群聊、成员/计划和历史，使用 `live-store.ts` 管理发送回执、游标、生成及重连。基础意识系统选择本窗口近期原文，详情页明确说明摘要/长期记忆尚未接入。发送期间只等待消息保存回执，AI 生成不阻塞继续输入；没有模型仍可保存消息。设置返回原窗口并刷新可选模型；编辑/撤回、成员/窗口暂停、结束交谈和归档/恢复均走共享业务命令。

`build:social-runtime` 输出到忽略的 `.social-runtime-dist`，供本地服务与 GUI 验收。Web 与 Tauri 均默认显示真实社交界面，`?legacy=1`/`?demo=1` 保留迁移期旧入口。浏览器只在 `llm-nest-social-live-drafts-v1` 保存真实界面的草稿和重试 ID，历史从后端读取，不与下面的预览 key 混用。实际能力见 [已完成](completed.md)，接口与事件见 [共享契约](07-api-and-events.md)。

## 当前真实桌面

共用 `social/App.tsx` 和 `live-store.ts`，`client.ts` 按 IS_DESKTOP 选择 HTTP 或 Tauri 适配器。桌面通过 invoke 发送业务命令、通过 Channel 接收共用订阅；初始化失败显示真实错误，不切换到 HTTP 或模拟回答。切换设置/通讯录/聊天不停止 AI；页面重载释放旧订阅，重新读取快照与已保存历史。

Windows 社交界面为现有窗口控制预留 56px 顶栏和拖动区域；Linux 保留系统装饰与真实 IPC。窗口控制和退出保存错误提示独立于业务初始化。关闭主窗口等待 Runtime 中断运行、保存片段并关闭 SQLite writer；20 秒超时或保存失败时保持窗口打开并提示再次关闭，不声称已经保存成功。验证范围见 [桌面实现记录](m1-desktop-ipc.md)。

## 当前 Web 交互预览

2026-10-08 起，先在 `frontends/web/src/social` 完成可操作的模拟界面。启动使用 `pnpm --dir frontends/web dev:social --host 127.0.0.1`，访问 1420 端口；普通 Web 开发页也可显式添加 `?social-preview=1`。预览继续与真实入口独立，不自动替代失败的连接。App 按需加载界面，窗口控制仍独立于业务初始化。

| 已实现交互 | 当前预览行为 |
| --- | --- |
| 导航与路由 | 消息/通讯录两个主入口，设置独立；聊天、联系人和记忆详情支持 hash 路由 |
| 身份与窗口 | 创建/编辑 AI 联系人时保留独立身份；每个联系人一个私聊，群聊另建；归档与恢复保留原 ID |
| 消息 | 文本发送、发送者与时间、引用回复、编辑与撤回；已提交历史与草稿跨刷新保存 |
| 参与控制 | 群内通过邀请选择器 @ 成员，回复 AI 时自动选中对方；每个空间顺序模拟回复，可停止一次、暂停空间或结束这一轮 |
| 意识管理 | 私聊/联系人详情共用关系记忆；群详情管理群记忆；手动添加、编辑、遗忘与来源状态 |
| 摘要与接续 | 按窗口展示摘要；整理预览为最近完整原文摘录；共同群消息引用到原有私聊，保留草稿与来源版本 |
| 外观与设置 | 浅/深主题、窄屏列表与聊天切换；保留现有设置界面，在预览中使用演示配置 |

模拟适配器 `mock-api.ts` 负责规则、保存和流式计时，视图只调用 `SocialApi`。数据 key 为 `llm-nest-social-preview-v1`，草稿 key 为 `llm-nest-social-preview-drafts-v1`；设置复用既有 `llm-nest-demo-*` 数据，与真实 Runtime 数据隔离。模拟保存先成功写入 localStorage，再替换内存；失败保留输入并提示。刷新将未完成回复标为中断，不重新执行。预览供单浏览器标签交互检查，尚无正式多端同步、存储锁和数据迁移。

模拟预览对来源编辑/撤回标记依赖记忆和摘要失效，旧引用发送时复核版本与共同群成员；私聊后续不写回源群。预览成员固定；预览不能验证后端成员变更与来源隔离。

模拟回复为固定模板，不读取完整模型上下文或记忆，也不调用模型或工具。模型绑定、主动联系、群成员变更、分段摘要、自动提取/Dreaming、附件与持久事件订阅尚未接入预览；真实 HTTP 社交能力另见上节。预览正文按文本显示，真实界面复用既有 Markdown 与执行展示。

验证：前端 typecheck、原有回归与新增 `tests/social-preview.cjs` 通过，`build:social` 通过且产物仅写入忽略的 `.social-preview-dist`。新测试覆盖唯一私聊、请求幂等、群邀请、停止/暂停/结束、来源权限与版本失效、保存失败回滚、重复发送抑制、迟到确认保留新输入及刷新恢复。浏览器实际操作检查了创建联系人与群、群话题接续私聊、记忆保存和摘要整理、设置往返/刷新保留草稿，以及 1280×720 和 430×820 浅/深主题；旧 Web 演示入口仍能启动，普通 Web 后端不可用时显示失败且不自动模拟。未进行真实 API、数据库、IPC、桌面打包或安装验收。

## 1. 信息结构

主导航只有“消息”和“通讯录”两个入口。消息页显示持续私聊与独立群聊，通讯录显示稳定 AI 联系人；设置通过独立按钮进入，记忆管理嵌入聊天详情和联系人详情。首版不增加记忆主导航、公开广场或推荐信息流。

意识系统（Consciousness）是统一后台机制。详情页继续使用“记忆”“历史摘要”“引用来源”等具体标签，帮助用户理解操作；系统命名不增加“意识”主导航，也不将后台任务状态显示成角色清醒或睡眠状态。

| 区域 | 默认展示 | 详情与操作 |
| --- | --- | --- |
| 消息列表 | 名字/群名、头像、最后完整消息、未读与置顶 | 暂停标记、归档、搜索 |
| 私聊顶部 | 对方身份、参与状态 | 档案、共同记忆、主动联系设置 |
| 群聊顶部 | 群名、成员 | 成员管理、参与模式、群记忆 |
| 通讯录/联系人详情 | 身份档案、唯一私聊入口 | 相处设置、关系记忆与执行配置 |
| 消息正文 | 发送者、时间、回复对象、正文或附件 | 编辑修订、撤回、再次回应、来源、与某 AI 私聊继续 |
| 运行详情 | 可折叠的执行状态 | 用量、计时、思考、工具与错误 |

模型选择、reasoning effort、temperature 和工具授权移到 AI 档案的高级配置。常规聊天仍显示明确的 AI 标记，不用模型名替代角色名。更换模型后的行为差异通过配置变更提示表达，不声称人格必然完全一致。

## 2. 路由与组件落点

主入口路由为 `#/messages` 和 `#/contacts`。聊天使用 `#/messages/{conversationId}`，聊天详情及记忆使用 `#/messages/{conversationId}/details` 与其 `/memories` 子页；联系人详情使用 `#/contacts/{actorId}`，关系记忆位于其 `/memories` 子页。现有 `#/settings/models|generation|appearance|config|about` 保留。`#/chat` 在迁移完成后兼容跳转到最近空间；未知或无权访问的 ID 显示可恢复状态。

点击同一联系人始终打开同一个私聊 ConversationId；群列表每项打开对应独立群窗口。结束当前交谈、更换模型或切换话题不清空记录，也不新增联系人私聊。

打开归档窗口保持只读，提供显式恢复操作；恢复使用原 ID，并在保存成功后允许发送，不自动重放归档前的队列。

M2 在群消息菜单加入“与某 AI 私聊继续”：选择拥有该段群历史访问权的 AI，打开其唯一私聊，在输入区带上可查看来源的引用条，发送后与用户消息一起保存。用户可调整或移除选中的范围；切换窗口后未发送引用随该私聊草稿保留，单纯导航不会自动发消息。AI 无源访问权时改为用户明确选择转发内容，不把源群全文直接注入私聊。

组件按领域拆分为 contacts、conversations、messages、consciousness、participation 与 settings。consciousness 包含 MemoryPanel、SummaryPanel 和引用来源展示，仍嵌入两种详情。布局重写现有 Sidebar/Header/ChatView 的业务部分，继续复用基础 UI、Markdown、代码与 Mermaid 渲染。

输入草稿按 conversationId 保存；档案和设置表单按对象保存。切换页面不会停止运行、清空输入或重复建立订阅。隐藏聊天 Header 时卸载菜单 portal，避免覆盖其他页面。

## 3. 状态管理

| Store | 负责内容 |
| --- | --- |
| actorStore | 档案、执行可用状态与联系人列表 |
| conversationStore | 会话列表元数据、成员、当前空间与已读位置；不保存生成的历史摘要 |
| messageStore | 分页消息、临时发送记录与修订 |
| runStore | 按 RunId 管理生成片段、活动与终态 |
| consciousnessStore | 按范围管理记忆条目、历史摘要与引用来源；M2 编辑/遗忘，后续候选确认 |
| participationStore | 暂停、成员模式、交谈与联系意图 |
| connectionStore | 订阅生命周期、cursor、重连与补齐状态 |

上表描述状态职责，不强制拆成七个 store；当前真实实现集中于 live-store.ts，按实际复杂度拆分。AI 生成不通过全局 isStreaming 阻塞输入。输入是否可发送取决于当前空间访问、历史加载、附件状态和存储连接；AI 生成状态单独管理。

真实社交已允许先保存真人消息，再判断 AI 是否可执行。无模型时给出“消息已保存，该 AI 需要配置”的明确状态；旧 Harness 入口仍禁止无模型发送。

## 4. 发送、流式与重连

当前发送保存草稿、requestId 和 sending 状态；成功回执合入服务器消息，失败保留输入与重试 ID，不预建持久真人或 AI 消息。未来如加入乐观发送气泡，其 sending/failed_to_send 仅是传输状态，不能伪装成后端消息。

真人消息保存成功不预建 AI 消息。后端 run_changed/message_changed 引用到达后读取运行与消息建立生成展示，标明谁正在输入、回应哪条消息。生成期间用户可继续输入和发送。

消息持久状态与传输状态分开。SocialMessage 的 committed/generating/interrupted/withdrawn 与 AiRun 的 cancelled/failed 分别表达，不能与发送失败混用；最终记录覆盖临时缓冲。新消息未读以完整可见消息为准，自身消息不增加未读。

订阅在应用级维护一个实例，页面读取共享 store。持久事件按 ID 去重并按 cursor 顺序应用；状态获取失败先重试或重新快照，不提前推进 cursor。终态后不接受旧 delta。

重连时显示连接与补齐状态，先恢复服务器权威记录和活动运行；不继续拼接断线前无法核对的 token，也不把断线展示为 AI 主动结束聊天。

## 5. 三种停止操作

- “停止这次回复”：cancelRun，只中断选定运行。
- “暂停 AI 参与”：pauseMember 或 pauseConversation，停止后续自动回应；真人仍可记录消息。
- “结束本次聊天”：endBout，保留关系与空间，取消本 Bout 接话队列并中断其活动运行；独立未来约定保留。

这些操作在按钮、菜单和状态文本中明确区分。暂停后的恢复是显式动作；约定联系是否继续在详情中可见，关闭主动联系会取消相应意图。

## 6. 意识系统的管理入口与资料

私聊详情与联系人详情访问同一份关系记忆；群详情管理本群记忆。联系人详情中的群记忆入口跳转到对应群，按权限展示，不把各空间记忆默认混合成一个公共档案。

首个记忆面板显示文本、范围、来源、有效状态和更新时间，提供添加、编辑和遗忘；后续自动候选加入后提供确认/拒绝。群里的共同记忆与私聊记忆分别展示，分享内容需要用户明确选择。近期消息与历史摘要可在聊天详情解释来源，完整原记录保留在消息列表。

聊天详情中的“历史摘要”按窗口显示分段、覆盖范围与更新状态。未来联系人详情可提供角色/关系“记忆概览”，它汇总该视角允许使用的信息，与聊天摘要分别标注。跨窗口接续在消息中显示可跳转的群来源，后续私聊内容不自动共享回群。

M1 只提供基本上下文链路，M2 加入上述记忆、摘要和接续界面。遗忘说明指明移除记忆条目及其派生使用，聊天原文另由撤回/清除控制；不把“遗忘”显示成完整聊天已删除。M2 持久摘要变更引用使详情重新读取当前摘要，迟到任务不能恢复失效材料。

AI 创建流程先填写身份，再选择执行配置；可以保存未配置模型的档案。群创建与邀请时说明当前成员共享完整群历史；@ 和回复用于选择接话对象。归档、撤回、清除历史与遗忘的影响分别表达，不使用一个含糊的“重置”按钮覆盖全部行为。

异步记忆提取失败有独立任务状态，不能把已经完成的回答显示为失败。角色和关系数据保存失败保留表单草稿，提供明确重试。

## 7. 平台约束

Tauri 与 Web 已共用真实社交组件、状态和业务 DTO，分别使用 IPC 与 HTTP client；U0 预览继续使用独立 SocialApi 模拟适配器。demo 使用明确标记的模拟数据与独立存储，不能自动替代失败的真实后端，也不能用 demo 验收证明数据库或调度成功。

首版不新增托盘或隐形常驻服务。窗口最小化时运行时仍可执行；关闭主窗口按上述流程完成中断收尾后退出。应用实际退出后主动联系停止，后续后台常驻需要独立的设置、状态与验收。

保留 IS_DESKTOP 与 CUSTOM_WINDOW_CHROME 的区别，Linux 使用桌面 IPC 与系统装饰。窗口控制独立于聊天初始化，历史/配置/存储失败可提示和重试。

Windows 已验收的透明 WebView 合成、不透明 HTML、原生底色同步、DWM 圆角与贴边细边框继续保留。应用 identifier、安装目录、升级标识与图标唯一源不随社交界面重写改变。

构建仍将桌面前端输出到忽略的 `frontends/tauri/dist`，不修改已跟踪 Web dist 或强制提交生成权限 schema。目录打开能力继续限制为 config/data 枚举。

## 8. 验收

1. 私聊、群聊和联系人切换保留输入、表单与运行。
2. 一个空间生成时，另一个空间可发送并显示后台新消息。
3. 保存失败、模型不可用和订阅断线使用不同提示。
4. 暂停、取消和结束各自作用正确，按钮键盘可用且状态可读。
5. 页面隐藏不留下菜单 portal，订阅不会随切换重复建立。
6. Web、Windows IPC、Linux IPC 字段与行为一致；窗口和打包基线无回归。
7. 主导航仅消息/通讯录；两种详情的关系记忆编辑保持同步，群记忆始终具有空间归属。
8. 重复打开、归档恢复和模型切换保持私聊窗口唯一，摘要处理不删除历史。
9. 群消息接续私聊保留明确来源与未发送草稿，不重复创建窗口、不因点击而自动发送，也不回传私聊内容。
