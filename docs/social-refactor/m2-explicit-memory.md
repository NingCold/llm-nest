## 本批实现

组织原则是“窗口保存经历，AI 账号持有记忆，每次发言临时组织上下文”。记忆以 AI + 窗口管理，服务端推导 relationship 或 conversation 范围；不开放全局 Actor 记忆，不自动将私聊记忆带入群。

- SQLite v7 增加 memories、memory_revisions、memory_message_sources，顺序迁移和一致备份，旧迁移校验不变。条目包含类型、内容、作者、时间、状态、版本及手动/消息来源。
- 当前成员可管理本窗口记忆，创建/编辑时 AI 必须仍为成员。来源必须为同窗口 committed 消息的确定版本。AI 离群后保留查看/遗忘入口；管理员权限不会授予其他窗口访问权。
- 消息“记住”和手动添加进入同一用例。编辑/撤回原文将依赖条目标 stale；必须核对新版或明确改为手动记忆后再确认。
- 运行只读当前 AI 与空间的 confirmed 条目。必要触发消息与回复对象优先，记忆最多占剩余输入预算四分之一，按更新时间选择，整条容纳不了则跳过。近期聊天使用剩余预算；快照只保存实际使用的 ID/版本，不复制请求正文。
- 新记忆只影响新运行。修改/遗忘提升窗口 context_epoch，在事务内中断在飞回复，Feature 随后取消生成流，最终提交仍复核记忆及来源版本。本批采用窗口级失效，不实现逐条依赖的精细取消。
- 遗忘清空记忆及修订正文，保留范围/来源/tombstone；原聊天、已发布回答和备份保留，不承诺 SQLite 物理页安全擦除。后续自动提取必须利用遗忘标记阻止同来源自动恢复。
- HTTP 增加 3 个路径，IPC 增加 4 个命令，共用 DTO 和 SocialFeature。memory_changed 只含引用，命令回执保留幂等、版本冲突和事务回滚。共用 React 状态层按范围顺序读取记忆，应用成功后才推进游标，失败重放、resync 重读已查看范围；详情和消息编辑保留输入与重试身份，来源查看复用单条消息接口。
