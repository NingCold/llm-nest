# 桌面窗口与设置页验收（2026-09-13）

## 改动与原因

- 修复 EXE 内嵌 Windows 图标仍为蓝色占位图。当前 `tauri-build 2.6.3` 没有为 ICO 输出构建依赖，增量构建会复用旧 PE 资源，而 `generate_context!()` 已读取新 ICO，导致窗口图标与 EXE/快捷方式图标不一致。`build.rs` 显式跟踪 `icons` 和 `capabilities`，修改图标会重新嵌入资源。
- NSIS 安装器与卸载器显式指定同一白底 ICO。应用内标识继续使用浅色黑标、深色白标。
- 关闭系统装饰标题栏，右上角提供最小化、最大化/还原、关闭。窗口控制独立于后端初始化，配置错误页仍能关闭窗口。顶栏和品牌区域声明 Tauri 拖动区域。
- Web 与桌面继续共用 `frontends/web`。设置使用独立页面，分为模型服务、生成参数、外观、关于；支持 `#/settings/<分类>`、返回聊天、浏览器前进/后退及 Ctrl/Cmd+逗号。
- 保留聊天组件与设置表单的挂载状态，切页不丢输入草稿、不取消在途回复；切页时卸载 Header，避免 Radix 菜单的 portal 残留覆盖设置页。供应商表单仍使用现有后端接口。
- 增加 `scripts/verify-windows-icons.ps1`：复制到唯一临时路径后提取可执行文件的系统图标，与源 ICO 比较，避免只看前端图片就误判发布包通过。

## 安装目录与验证边界

- 旧开始菜单指向 `E:/Program Files/LLM Nest`；该目录对当前账号不可写。向此目录运行 NSIS 静默安装曾返回 0，但文件未更新，因此**不能仅依赖安装器退出码判定升级成功**。
- 新版实际安装在 `%LOCALAPPDATA%/Programs/LLM Nest`，桌面和开始菜单快捷方式均已指向该目录；保留无法覆盖的旧 E 盘副本。最终安装结果按实际文件内容和内嵌图标复核。
- 图标脚本检查的是 Windows 提取的 32px 资源表示，不替代所有 DPI、所有尺寸、已固定任务栏缓存的视觉检查。未清理系统图标缓存或重启资源管理器。
- 顶栏拖动与边缘缩放已配置，但本轮自动化拖动未取得可靠的移动/尺寸变化证据；800px 无边框窗口、拖动手感、多显示器和不同 DPI 仍需人工复核。前一轮 800px 的结论属于旧的带标题栏版本。
- 本轮没有新增真实厂商请求；前一轮 ecnu-max 的结论见单独报告。
- 本机不是干净系统；未验证缺少 WebView2 的首次安装，也未进行 MSI 系统级安装/升级/卸载。MSI 行政解包只核对文件，不等于完整安装。

## 待验收术语

| 术语 | 实际含义 |
| --- | --- |
| 干净 Windows | 在没有项目开发环境的全新系统上安装，确认不会依赖开发机已有的软件。 |
| 缺少 WebView2 | Windows 缺少渲染桌面界面的 WebView2 Runtime 时，安装器能否完成依赖安装并启动应用。当前配置为联网下载引导程序，不是完全离线安装包。 |
| MSI 系统级安装 | 通过 Windows Installer 为系统/所有用户安装，检查权限、升级、修复、卸载与数据保留。 |
| 沙盒入口 | `.wsb` 配置及安装包、哈希、验收清单，用于启动一次性的隔离 Windows 环境。准备好入口不代表沙盒已启动或验收通过。 |

本机没有可用的 Windows Sandbox/虚拟机，未启用系统功能、重启或申请管理员权限。步骤见 [干净 Windows 安装验收](windows-clean-install.md)。
