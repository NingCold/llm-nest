## 下一批：首版本地社交体验收尾

目标是把现有功能作为一个应用连续使用，找出并修复实际断点。本批统一完成下列流程，不将每一行再拆成独立开发批次：

| 使用流程 | 要确认的结果 |
| --- | --- |
| 从空配置开始，配置模拟模型，创建三个 AI，分别私聊并建立共同群 | 引导和入口清楚，身份、唯一私聊与群成员一致；未配置模型时仍能保存真人消息并看到提示 |
| 群里讨论后带话题回私聊，管理显式记忆和窗口摘要 | 相关内容能接续，来源可查看，修改与遗忘的界面和实际请求一致 |
| 连续输入、群内接话、暂停/结束、创建一次约定并使用免打扰 | 当前谁在回复、如何停止、约定是否执行都能理解，已有控制规则保持有效 |
| 查找旧消息、置顶/标记未读、移除或屏蔽联系人，再恢复联系 | 能找到原来的窗口与历史，关系操作的影响清楚 |
| 发送文字、图片和普通文件，保留未发送草稿，导出带附件的聊天，再刷新或重启 | 消息、草稿、附件和个人列表状态按既有规则保存，导出文件可实际使用 |

先复用已有脚本和验证证据，在 Web 上走完整流程，并检查受影响的共用业务与 HTTP/IPC 链路；补充缺失的组合验证，修复实际发现的问题。需要原生窗口、WebView 或安装环境才能确认的项目归入[平台验收](pending.md#m1-剩余范围)。默认使用隔离数据和模拟 provider，不以此声称真实模型或桌面实机体验已通过。

**本批结束条件：上述流程通过，妨碍流程完成或造成数据/权限错误的问题修复并复验，验证范围和平台未测项记录清楚。** 一般改进建议保留为候选，不反复扩大收尾范围；已有检查通过后不无故重复全量构建。
