# 图片消息第三批：未发送草稿保存与恢复

2026-10-13。[当前进度](in-progress.md) · [存储规则](06-storage-and-migration.md#本机未发送草稿) · [界面说明](08-frontend-and-desktop.md) · [上一批记录](image-message-export.md)

## 使用方式

选好图片、输入文字后，输入框下方显示保存进度。看到“草稿已保存在本机”后，刷新页面或重开应用都可以继续编辑。文字、图片、回复对象、提及和群话题引用一同恢复；私聊和各个群各自保留草稿。

Web 草稿属于当前浏览器及访问地址（包括端口）；桌面草稿属于应用的 WebView。两者不会互相同步，清理网站或应用浏览数据会删除草稿。图片仍按前两批限制选择，不重新编码。

如果上次发送结果尚未确认，恢复后会显示“重试上次发送”和“放弃重试”。可以展开查看上次的文字和图片；重试沿用原内容，当前新输入保留。恢复不会自动发消息。放弃重试不会撤回可能已送达的消息，当前可编辑草稿仍保留。

读取草稿失败时显示重试入口，恢复成功前禁止编辑，避免用空输入覆盖旧数据。写入失败时保留页面内容并提示重试；多个页面同时编辑同一个窗口时，旧页面会提示冲突，需要先保留当前输入，再刷新读取另一页的版本。

## 实现

`drafts.ts` 定义可编辑草稿、待确认快照和发送成功后的清理规则。`draft-storage.ts` 使用 IndexedDB v1 的 `drafts` 表，键为实际真人账号和窗口 ID；每次事务比较版本后写入文字、图片 Blob 与元数据、目标/引用及 pending 快照。事务完成才更新“已保存”，不把 base64 图片塞入 localStorage。Blob 转换按不可变图片对象缓存，避免每次输入文字都重新解码。

`live-store.ts` 按窗口串行保存，发送前先等待完整 pending 命令落盘。丢失回执后重开仍能用同一 requestId 和内容重试；收到成功回执只清理对应原草稿与已发送图片，保留等待期间新增内容。清理失败会明确提示，已经收到的聊天记录仍展示成功；下次打开可继续用原命令核对回执。

当前新版的旧文字草稿 key `llm-nest-social-live-drafts-v1` 在首次读取时迁入当前账号可见窗口；迁入成功后才清理这些旧条目，其余保留。清空后的数据库记录保留版本及空内容，不再引用图片 Blob，防止迁移中断后旧草稿复活。早期独立预览数据不参与迁移。

草稿不经服务器保存，不触发 AI、已读或持久事件，也不加入聊天导出；SQLite 仍为 v13。群话题引用只保存来源 ID/版本，发送时继续走既有权限及版本检查。

存储使用 [IndexedDB 事务](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction) 和 strict durability；确认事务完成不等于跨设备备份，也不保证清理浏览器数据或磁盘损坏后的恢复。

## 关闭流程

Web 在有未完成图片读取/写入或保存错误时请求浏览器的离开提示；浏览器是否显示仍取决于自身策略。正常刷新读取已提交草稿。

桌面前端注册 page UUID，关闭主窗口时宿主发送 `drafts-prepare-close`。页面暂停编辑，等待已经开始的图片读取与草稿事务，重试此前失败的写入，再用 page/request 确认；已屏蔽或归档窗口的草稿也可以随再次关闭重试保存。宿主只接受当前页面与本次请求的确认，10 秒超时或失败保留窗口与可用后端。页面重载/销毁释放旧等待，旧页面的注销不能移除新页面注册。

确认后才进入既有 Runtime 关闭过程：拒绝新业务命令、释放订阅、中断保存、排空 SQLite writer，最多等 20 秒。初始页面尚未注册时可以关闭，不阻止启动失败后的退出。命令及事件详见[接口文档](07-api-and-events.md#6-启动订阅与补齐)。

## 验证与范围

- Web 类型检查、14 组测试脚本和生产构建通过。新测试用实际草稿模块配合 `fake-indexeddb`，覆盖 Blob 原始字节、中文名称、账号/窗口隔离、文字草稿迁移、回执丢失后的完整命令恢复、禁止自动发送、发送期间新输入、移除/清空、读取/配额/清理失败、多页版本冲突、未完成图片读取及关闭等待。`fake-indexeddb` 仅为开发测试依赖。构建保留既有的较大 bundle 与动态导入提示。
- Windows MSVC：`cargo test -p tauri-frontend --locked` 13 项通过，包括关闭 page/request 匹配、失败后重试、重载释放及旧页面注销；`cargo fmt --all -- --check` 与受影响模块 Clippy 完成。Clippy 保留 ai-client 原有 5 条风格提示，本批未修改该模块。
- 实际浏览器通过独立配置、临时数据和本地模拟 provider 验证：选图与文字保存、刷新恢复、关闭标签后重新打开、私聊/群聊独立草稿、发送后刷新清理、移除图片后刷新不复活。后端核对恢复的图片只发送一次，消息图片与源文件 SHA-256 相同；群草稿没有自动发送。控制台未发现警告或错误。
- 恢复后的截图保存在忽略目录 `target/image-drafts-web.png`；测试日志与临时夹具均不提交。

本批未使用个人配置或付费模型，未更新本机安装程序。浏览器关闭标签再打开的验证不代表已经重启整个浏览器进程或操作系统；真实 Windows/Linux WebView 的关闭/重开、保存中关闭与错误提示仍待平台实测。暂缓的安装任务保持原安排。
