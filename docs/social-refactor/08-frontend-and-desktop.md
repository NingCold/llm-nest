## 当前视觉与布局

共用 React 界面参考 Codex 的连续表面与紧凑侧栏，采用中性灰白 / 炭黑底色与克制的蓝色强调，继续使用已有 Tailwind、Radix 和 Lucide；社交语义样式集中在 `social.css`，设置通过同一组变量衔接。无需增加动效库、远程字体或图片依赖。

| 用途 | 浅色 | 深色 |
| --- | --- | --- |
| 主背景 / 侧栏与面板 | `#ffffff` / `#f6f6f6` | `#181818` / `#202020` |
| 正文 / 辅助文字 | `#242424` / `#747474` | `#ededed` / `#a0a0a0` |
| 边框 / 链接与焦点强调 | `#e8e8e8` / `#3573c4` | `#303030` / `#8cb8ed` |
| 主操作按钮 | `#242424` 配白字 | `#ededed` 配炭黑字 |

聊天正文与输入为 15px，表单与联系人名称为 14px，列表摘要和按钮为 13px，时间及辅助说明为 12px，AI 标签为 11px。桌面将主导航、列表与自己的账号合为 288px 侧栏，“消息 / 通讯录”横向切换；聊天顶栏 72px，消息与输入区限制在 800px 居中。真实聊天的 AI 正文去掉外框，自己的消息为柔和灰色气泡，输入区为低阴影圆角表面；Markdown 表格和代码在自身区域横向滚动。

大窗口的详情占独立一栏，1050px 以下为覆盖面板，700px 以下为全宽详情。850px 以下采用列表 / 内容切换；700px 以下在列表和账号页使用底部导航，进入聊天后隐藏底部导航，用聊天顶栏返回。设置在手机宽度下改为顶部横向分类。浏览器视口检查不代替手机软键盘实机验收。

公开账号资料使用紧凑身份区及简介、ID、关系区，不使用大封面；真人与 AI 仍共用资料结构。管理页使用横向账号选择、身份与操作区、内部设定 / 执行配置、管理员 / 运行状态；宽窗口两列，窄窗口一列。长名称在选择器中截断，在详情中换行，选中账号保持可见。普通资料不展示执行参数。

消息列表显示当前窗口的未发送草稿。生成状态标注具体发送者，停止按钮明确当前 AI 回复，继续发送仍可用。弹窗保留 Radix 的键盘行为，关闭后回到触发按钮；主导航与当前列表项有 `aria-current`。颜色过渡为 160ms，详情进入为 180ms，桌面首次界面淡入为 220ms；减少动态效果偏好会关闭动画与过渡。早期验证见 [界面现代化记录](m1-ui-modernization.md)，当前布局与启动验证见 [桌面启动记录](m1-desktop-surface.md)。

## 消息列表与搜索

消息列表提供全部/未读筛选，数字提示新到消息、蓝点提示手动未读；每行菜单可置顶/取消置顶和标为已读/未读。状态保存在本地服务中，Web 与桌面重开后沿用。置顶优先，同组按最新完成的消息排序。当前聊天手动标未读会返回列表，等再次打开最新聊天时再确认。

自动已读要求页面可见、窗口有焦点、当前为正常聊天且滚动在底部，最新历史读取成功后等待 500ms 确认。翻看历史、定位搜索结果、切到账号/设置或失焦时不确认；确认失败显示错误，保存成功才刷新状态。主导航也显示未读提示。

“搜索聊天和正文”保留按名字/群成员过滤，同时查询全部保存的正文；打开聊天时可以把正文范围改为当前聊天。搜索延迟 250ms，每页 50 条，可继续加载与失败重试；新查询、范围或来源变化丢弃迟到读取。选中结果进入原窗口的 `#/messages/{conversationId}/at/{messageId}`，高亮原消息并显示前后记录；“返回最新消息”恢复普通聊天和已读确认。记录没有被复制进另一个窗口或浏览器持久缓存。具体范围见[实现记录](message-list.md)。

## 图片消息

输入区在草稿有图片、群引用或回复图片时显示支持/不支持/未知。私聊显示对方，群聊有结构化 @ 或回复 AI 时显示目标，否则显示当前所有 AI 成员；不改变群接话规则，不禁用真人发送。普通聊天只消费账号能力标识，不接触内部模型绑定。历史图片和群引用是否进入本次请求，由后端意识系统及 AiClient 统一检查；明确不支持时显示执行原因，其他群成员仍能回复，详见[图片能力记录](image-capabilities.md)。

输入框可选择、拖入或粘贴 PNG/JPEG/WebP，预览、移除后发送，允许纯图片。每条最多 4 张，单张 4 MiB、合计 8 MiB，边长 4096。超出尺寸或大小时打开“发送前处理图片”；已有草稿缩略图旁也有主动处理按钮。可以选择最长边 4096/2560/1600/1024、WebP/JPEG/PNG 和有损质量 90%/80%/65%，默认 2560、WebP、80%。图片按比例缩小，不放大小图；PNG/WebP 保留透明，JPEG 用明确白底。

原图与处理预览并排显示，可点开放大，并显示各自尺寸、文件大小和全部图片总量。生成预览不发送、不保存为草稿；选项变化清除旧预览，仍超限则不能确认。确认时才加入或替换目标窗口的图片草稿，保留文字/回复等输入；取消与迟到结果均不修改草稿。处理结果为静态图片且不保留拍摄信息，原文件不改写。待处理源单张最多 20 MiB、解码后最多 6400 万像素；超出时提示先在其他图片编辑器缩小。详情见[图片处理记录](image-processing.md)。

未发送草稿将文字、图片与提及/回复/群话题引用一起保存在 IndexedDB，刷新或重开同一浏览器地址/桌面应用后恢复。按实际真人账号与窗口隔离，恢复完成后才能编辑；保存中、保存成功、保存失败及重试入口直接显示在输入区。多个页面修改同一草稿时提示冲突，不覆盖另一页的内容。

发送前先持久保存原内容与 requestId；结果未知时保留独立快照，重开后可查看原内容、手动重试或放弃重试，不自动发出消息。放弃不撤回可能已送达的消息。成功回执清理对应图片和原草稿，保留等待期间新增的内容。Web 在还有未完成图片读取/写入、保存错误或未确认的图片处理时，通过 beforeunload 提示；桌面关闭流程见下文。草稿只在当前浏览器或桌面 WebView 保存，不属于服务器历史、跨端同步或整库备份，清理网站/应用浏览数据会删除草稿。实现与验证见[图片草稿记录](image-drafts.md)。

历史图片进入可见范围时读取，失败提供重试，点击放大使用共用 Radix 对话框。已发送图片的预览提供“保存原图”，保存时重新读取当前权限与版本，不使用预览缓存；待发送草稿不显示这一按钮。处理后发送的图片，下载和导出均使用处理后的字节，不保留可回取的处理前副本。撤回、修订和引用失效切换会卸载旧图；迟到读取不覆盖新版。普通聊天、搜索定位、群来源预览和管理员只读账号视角使用同一图片展示，账号视角经专用权限读取。消息列表和纯图片回复引用显示“[图片]”。

Web 与 Tauri 共用 File 输入；桌面公共/Windows 配置的 dragDropEnabled=false 让 WebView 接收文件拖放，不增加任意文件路径读取。原生桌面文件选择、拖放与剪贴板仍需平台实测。详情与验证见[图片消息记录](image-messages.md)。

## 当前真实 Web

普通 Web 开发和生产入口使用 `social/App.tsx`，通过 HTTP 读取 SQLite 的公开账号、个人通讯录、唯一私聊、群聊、成员/计划和历史，使用 `live-store.ts` 管理发送回执、游标、生成及重连。意识系统选择本窗口近期原文、有效分段摘要和当前 AI 的有效显式记忆。聊天详情与联系人详情通过 LiveMemory 管理真实记忆：按 AI 选择归属、手动添加、编辑、查看来源和遗忘；消息上的“记住”绑定原文版本。来源变化显示 stale，需明确核对新版或转为手动记忆。列表根据持久变更后更新的快照重新读取，失败可重试，旧成功回执不会回放旧正文。LiveSummary 在同一详情中提供按窗口的摘要设置、任务状态、来源查看、下一段与失败/失效重建。默认关闭，需选择专用模型与输出上限；自动整理的调用费用在设置中说明。摘要变化通过有序读取更新当前列表，失败清空旧缓存且不推进游标；重连重新读取已查看范围。发送期间只等待消息保存回执，AI 生成不阻塞继续输入；没有模型仍可保存消息。设置返回原窗口并刷新可选模型；编辑/撤回、成员/窗口暂停、结束交谈和归档/恢复均走共享业务命令。

`build:social-runtime` 输出到忽略的 `.social-runtime-dist`，供本地服务与 GUI 验收。Web 与 Tauri 只显示真实社交界面；legacy/demo/social-preview 查询参数均不再切换入口。本地草稿由 `draft-storage.ts` 管理 IndexedDB，图片使用 Blob，当前新版早期文字草稿 key `llm-nest-social-live-drafts-v1` 只用于一次性迁入；历史从后端读取，不读取早期预览或 Harness 数据 key。实际能力见 [已完成](completed.md)，接口与事件见 [共享契约](07-api-and-events.md)。

当前通讯录提供“我的联系人 / 本地账号”。普通账号资料由 AccountDetails 共用，只有公开名字、类型、状态、简介、ID 和关系操作，不返回内部 persona/模型。移除只撤下个人通讯录条目，仍可继续私聊和共同群互动；重新添加沿用原窗口。账号状态与列出状态分别展示，停用账号可仍列在通讯录中。

LiveParticipation 在聊天详情提供接话规则：私聊等待毫秒数、空闲结束秒数、群聊显式自动参与及连续/Bout/每日次数和 token 预留上限。界面解释 UTC 日与保守预留，显示等待原因、已用额度和自动/合并计划；群头部与输入区提示随模式变化。表单未知保存结果保留输入与重试 ID，版本冲突不覆盖后端规则。

点击侧栏自己的头像进入“我的账号”，其下的 AI 角色管理页提供创建、内部设定/模型/思考强度/温度/输出上限、管理员列表、初始管理员授予/撤销和停用/恢复。生成字段使用后端的模型/思考模式约束，非法值显示原因并阻止保存；切换模型保留已填值，不支持温度时提供明确的清空按钮。留空使用模型服务默认温度和意识系统自动输出预算，不继承全局设置。管理页的“登录 AI 账号查看”进入只读视角，显示实际管理员与被查看 AI，只读取它参与的窗口和自己的通讯录，手动刷新；不代发消息、不切换后端操作者、不取消运行。普通聊天/联系人详情已接入显式记忆；管理员只读账号视角仍只展示快照与聊天历史，不提供记忆代编辑。Web/桌面共用 AccountPages 与业务权限，验证见 [账号管理记录](m1-account-management.md) / [参数记录](m1-generation-parameters.md)。

### 约定联系与免打扰

聊天详情新增约定联系面板，独立开关默认关闭；成员可以选择本窗口可发言的 AI、内容、联系时间和失效时间。日期使用本机时区，保存确定的 UTC 时点及所选日期的固定偏移；界面显示偏移，拒绝夏令时跳过的无效本地时刻。免打扰设置为一次截止时间，可延后或跳过，仅影响约定联系。正常回复继续；应用关闭时不运行，也不唤醒系统。

列表显示全部活动约定与最近 50 条记录，支持版本化取消；保存失败保留表单、未知结果沿用请求 ID。刷新与 contact_schedule_changed 重读窗口即可恢复状态，不缓存意图正文到浏览器。约定发出的消息保持 AI 身份且 replyTo=null。接话规则中的额度对私聊也显示，与约定联系共享。

## 当前真实桌面

共用 `social/App.tsx` 和 `live-store.ts`，`client.ts` 按 IS_DESKTOP 选择 HTTP 或 Tauri 适配器。桌面通过 invoke 发送业务命令、通过 Channel 接收共用订阅；初始化失败显示真实错误，不切换到 HTTP 或模拟回答。切换设置/通讯录/聊天不停止 AI；页面重载释放旧订阅，重新读取快照与已保存历史。

桌面后端内嵌于应用，通过 IPC 自动初始化，无需另开 Web Server。Windows 首次绘制先露出空白原生 Acrylic；React 模块与本地服务初始化期间保持空白启动层，成功或报错后才显现界面。失败保留实际错误、重试和设置入口，不能停留在空白层。Web 使用可读的加载提示。

Windows/Linux 关闭系统标题栏，社交页不再预留独立 56px 顶栏。窗口按钮嵌在内容右上角，相关内容头部留出按钮宽度；社交/设置侧栏空白、聊天与账号等页面头部支持原生拖动及双击最大化/还原，未选中聊天时的空页面自身空白也可拖动。交互元素与搜索框不拖动，聊天正文和账号正文保留文字选择；不使用覆盖内容的顶部拖动层。按钮、关闭收尾和错误提示独立于业务初始化。Linux 使用主题底色的空白启动层，当前改动尚未在 GNOME 实机复验，不声称已实现 Windows 原生磨砂玻璃。关闭主窗口先通过 `drafts-prepare-close` 让已注册页面停止编辑、完成正在读取的图片和草稿事务；尚有未确认图片处理时先要求确认或取消；10 秒未确认关闭或保存失败时保持窗口及后端可用并提示重试。收到当前页面/关闭请求的成功确认后，再等待 Runtime 中断运行、保存片段并关闭 SQLite writer；该阶段 20 秒超时或保存失败时保持窗口打开并提示再次关闭。原订阅与关闭范围见 [桌面实现记录](m1-desktop-ipc.md)，Windows 启动与拖动检查分别见 [启动记录](m1-desktop-surface.md) / [拖动记录](m1-desktop-drag.md)。

## 历史导入与隔离验证

设置仅有模型服务、外观、配置和关于。`/api/settings` / `settings_snapshot` 只返回模型服务和版本，初始化设置不再加载旧会话或全局生成参数。AI 参数在管理员角色面板维护。

模型服务中的“模型图片能力”显示当前三态与来源，允许跟随目录或人工覆盖。保存失败保留选择并提示重试，成功才更新状态；恢复跟随目录只移除能力字段。管理员选择 AI 模型时也显示能力和来源，调整声明不改变 AI 的账号或绑定。能力由目录/配置声明，不表示通过真实识图测试。

“配置 → 导入历史聊天”先检查当前数据目录，用户选择旧 JSON 记录后显式导入。失败保留选择；源变化需要重新检查，重复成功提交不会重复创建窗口。返回消息列表可读历史，原文件不修改，不自动接话。

早期 U0 独立模拟产品已退役。界面开发与验收使用 `social_acceptance.py --serve` 的临时 SQLite / mock provider 和同一真实界面；历史导入可用 `acceptance.py --serve`。不再提供 demo 回退或只在浏览器保存的模拟历史。

## 当前聊天导出

聊天详情的“聊天”页提供“导出聊天记录”，默认 Markdown，可切换 JSON，勾选“包含图片”后保存为 ZIP，内含所选格式的记录与原图。私聊、群聊、归档及已导入历史均显示该入口；不依赖前端已加载记录。导出期间禁用操作，失败保留所选格式与携图选项并允许重试，切换窗口重置提示。Web 显示“已开始下载”，桌面在文件写入完成后显示“已保存”，取消单独提示。未勾选时的附件占位和不附带记忆/思考/内部设定的范围在入口说明。

组件为 `ConversationExportPanel` 与 `ImageSaveButton`，客户端 `exportConversation` / `saveImage` 根据宿主使用 HTTP 文件下载或 IPC 原生另存为；业务读取与格式化共用 SocialFeature。桌面不向 WebView 开放通用文件写入或 dialog 插件命令权限。详见[图片导出记录](image-message-export.md)。

## 1. 信息结构

主导航只有“消息”和“通讯录”两个入口。消息页显示持续私聊与独立群聊，通讯录显示稳定 AI 联系人；设置通过独立按钮进入，记忆管理嵌入聊天详情和联系人详情。首版不增加记忆主导航、公开广场或推荐信息流。

意识系统（Consciousness）是统一后台机制。详情页继续使用“记忆”“历史摘要”“引用来源”等具体标签，帮助用户理解操作；系统命名不增加“意识”主导航，也不将后台任务状态显示成角色清醒或睡眠状态。

| 区域 | 默认展示 | 详情与操作 |
| --- | --- | --- |
| 消息列表 | 名字/群名、头像、最后完整消息、未读与置顶 | 暂停标记、归档、搜索 |
| 私聊顶部 | 对方身份、参与状态 | 档案、共同记忆、主动联系设置 |
| 群聊顶部 | 群名、成员 | 成员管理、参与模式、群记忆 |
| 通讯录/联系人详情 | AI 与真人一致的账号资料、唯一私聊入口 | 联系关系、相处设置与有范围的关系记忆 |
| 自己账号下的 AI 角色管理 | 所获授权的 AI 账号 | 内部设定、执行配置、停用/恢复、登录账号查看；初始管理员可授予其他管理员；不是第三个主入口 |
| 消息正文 | 发送者、时间、回复对象、正文或附件 | 编辑修订、撤回、再次回应、来源、与某 AI 私聊继续 |
| 运行详情 | 可折叠的执行状态 | 用量、计时、思考、工具与错误 |

AI 与真人账号详情采用同样的内容与界面结构，公开资料与 AI 内部设定分开。模型选择、reasoning effort、temperature、内部角色设定和工具授权在管理员自己的 AI 角色管理页面维护，普通联系人详情不提供这些专有字段或编辑入口。当前共同字段为名字、类型、状态、公开简介、账号 ID 和 avatarRef；头像上传尚未接入，界面使用名字头像。更换模型后的行为差异通过管理空间的配置变更提示表达，不声称人格必然完全一致。

初始管理员可从管理页面授予其他账号管理员权限。每个获授权 AI 提供登录账号查看的入口，进入该 AI 自身权限范围内的账号视角，明确当前被查看账号与实际管理员，并能返回自己的账号。首版入口用于查看，不提供人工代发消息；账号切换不取消 AI 自动执行。当前账号视角是带权限检查的快照与分页历史，手动刷新；没有为这个视角复用实际操作者的全局订阅。

关系级移除只撤下当前用户通讯录中的条目，历史与共同群互动保留；未屏蔽时允许继续私聊，重新添加沿用原 ConversationId 并保留屏蔽状态。联系人资料和私聊详情提供屏蔽/解除：首次屏蔽确认影响，保存失败保留操作；屏蔽私聊显示提示并保留草稿，解除后继续输入。共同群正常交流，约定表单排除已屏蔽对象。规则见[屏蔽记录](contact-blocking.md)。全局停用/恢复在管理员的角色管理页面操作，保留数据，恢复只响应新消息。

## 2. 路由与组件落点

主入口路由为 `#/messages` 和 `#/contacts`。聊天使用 `#/messages/{conversationId}`，聊天详情及记忆使用 `#/messages/{conversationId}/details` 与其 `/memories` 子页；联系人详情使用 `#/contacts/{actorId}`，关系记忆位于其 `/memories` 子页。自己的资料位于 `#/account`，角色管理使用 `#/ai-management` 与 `#/ai-management/{actorId}`，只读账号视角使用 `#/account-view/{actorId}`；均通过自己的账号进入，不增加主导航。现有 `#/settings/models|appearance|config|about` 保留。`#/chat` 按未知入口落到消息列表；未知或无权访问的 ID 显示可恢复状态。

点击同一联系人始终打开同一个私聊 ConversationId；群列表每项打开对应独立群窗口。结束当前交谈、更换模型或切换话题不清空记录，也不新增联系人私聊。

打开归档窗口保持只读，提供显式恢复操作；恢复使用原 ID，并在保存成功后允许发送，不自动重放归档前的队列。

真实群消息已提供“私聊继续”：选择当前共同 AI 成员、1–8 条附近已加载原文与可选相关摘要，预览校验成功后打开唯一私聊，加入可查看/移除的引用草稿。保留已有文字、回复和 @ 选择；替换引用会重置发送请求 ID，单纯导航不发送。引用草稿只持久化 ID/版本，不保存群正文；发送失败保留输入与同一重试 ID。来源卡每次按当前游标重新读取，断线/失效不显示旧预览，迟到读取不覆盖新状态。失效引用需回到群聊重新选择；自然语言定位与显式转发尚未实现。实现见 [第三批记录](m2-cross-window-continuation.md)。

组件按领域拆分为 contacts、conversations、messages、consciousness、participation 与 settings。consciousness 包含 MemoryPanel、SummaryPanel 和引用来源展示，仍嵌入两种详情。布局重写现有 Sidebar/Header/ChatView 的业务部分，继续复用基础 UI、Markdown、代码与 Mermaid 渲染。

输入草稿按 conversationId 保存；档案和设置表单按对象保存。切换页面不会停止运行、清空输入或重复建立订阅。隐藏聊天 Header 时卸载菜单 portal，避免覆盖其他页面。

## 3. 状态管理

| Store | 负责内容 |
| --- | --- |
| actorStore | 档案、执行可用状态与联系人列表 |
| conversationStore | 会话列表元数据、成员、当前空间与已读位置；不保存生成的历史摘要 |
| messageStore | 分页消息、临时发送记录与修订 |
| runStore | 按 RunId 管理生成片段、活动与终态 |
| live-store 中的记忆状态 | 按窗口/AI 顺序读取记忆、按窗口顺序读取摘要；分页与事件刷新串行，读取成功后推进订阅游标；引用选择随私聊草稿保存，来源预览按游标重读；自动候选确认留待后续 |
| participationStore | 暂停、成员模式、交谈与联系意图 |
| connectionStore | 订阅生命周期、cursor、重连与补齐状态 |

上表描述状态职责，不强制拆成七个 store；当前真实实现集中于 live-store.ts，按实际复杂度拆分。AI 生成不通过全局 isStreaming 阻塞输入。输入是否可发送取决于当前空间访问、历史加载、附件状态和存储连接；AI 生成状态单独管理。

真实社交已允许先保存真人消息，再判断 AI 是否可执行。无模型时给出“消息已保存，该 AI 需要配置”的明确状态。

## 4. 发送、流式与重连

当前发送保存草稿、requestId 和 sending 状态；成功回执合入服务器消息，失败保留输入与重试 ID，不预建持久真人或 AI 消息。未来如加入乐观发送气泡，其 sending/failed_to_send 仅是传输状态，不能伪装成后端消息。

真人消息保存成功不预建 AI 消息。后端 run_changed/message_changed 引用到达后读取运行与消息建立生成展示，标明谁正在输入、回应哪条消息。生成期间用户可继续输入和发送。

消息持久状态与传输状态分开。SocialMessage 的 committed/generating/interrupted/withdrawn 与 AiRun 的 cancelled/failed 分别表达，不能与发送失败混用；最终记录覆盖临时缓冲。新消息未读以完整可见消息为准，自身消息不增加未读。

订阅在应用级维护一个实例，页面读取共享 store。持久事件按 ID 去重并按 cursor 顺序应用；状态获取失败先重试或重新快照，不提前推进 cursor。终态后不接受旧 delta。

重连时显示连接与补齐状态，先恢复服务器权威记录和活动运行；不继续拼接断线前无法核对的 token，也不把断线展示为 AI 主动结束聊天。

## 5. 三种停止操作

- “停止这次回复”：cancelRun，只中断选定运行。
- “暂停 AI 参与”：pauseMember 或 pauseConversation，停止后续自动回应；真人仍可记录消息。
- “结束本次聊天”：endBout，保留关系与空间，取消本 Bout 接话队列并中断其活动运行；独立未来约定保留。

这些操作在按钮、菜单和状态文本中明确区分。暂停后的恢复是显式动作；约定联系是否继续在详情中可见，关闭主动联系会取消相应意图。

## 6. 意识系统的管理入口与资料

私聊详情与联系人详情访问同一份关系记忆；群详情管理本群记忆。联系人详情中的群记忆入口跳转到对应群，按权限展示，不把各空间记忆默认混合成一个公共档案。

首个记忆面板显示文本、范围、来源、有效状态和更新时间，提供添加、编辑和遗忘；后续自动候选加入后提供确认/拒绝。群里的共同记忆与私聊记忆分别展示，分享内容需要用户明确选择。近期消息与历史摘要可在聊天详情解释来源，完整原记录保留在消息列表。

聊天详情中的“历史摘要”按窗口显示分段、覆盖范围与更新状态。未来联系人详情可提供角色/关系“记忆概览”，它汇总该视角允许使用的信息，与聊天摘要分别标注。跨窗口接续在消息中显示可跳转的群来源，后续私聊内容不自动共享回群。

M1 提供基本上下文链路；M2 前两批已接入显式记忆与窗口分段摘要，第三批继续做群话题接续私聊。遗忘说明指明移除记忆条目及其派生使用，聊天原文另由撤回/清除控制；不把“遗忘”显示成完整聊天已删除。M2 持久摘要变更引用使详情重新读取当前摘要，迟到任务不能恢复失效材料。

AI 创建与配置已经位于自己账号下的角色管理流程；当前创建一起提交公开资料、内部档案、可选执行配置和初始管理权。群创建与邀请时说明当前成员共享完整群历史；@ 和回复用于选择接话对象。关系级移除、管理员停用账号、窗口归档、撤回、清除历史与遗忘分别表达，不使用一个含糊的“重置”按钮覆盖全部行为。

异步记忆提取失败有独立任务状态，不能把已经完成的回答显示为失败。角色和关系数据保存失败保留表单草稿，提供明确重试。

## 7. 平台约束

Tauri 与 Web 已共用真实社交组件、状态和业务 DTO，分别使用 IPC 与 HTTP client。U0 模拟适配器已退役；验收用临时数据和本机模拟 provider 驱动同一套真实界面及后端。

首版不新增托盘或隐形常驻服务。窗口最小化时运行时仍可执行；关闭主窗口按上述流程完成中断收尾后退出。应用实际退出后主动联系停止，后续后台常驻需要独立的设置、状态与验收。

保留 IS_DESKTOP 与 CUSTOM_WINDOW_CHROME 的区别：前者决定桌面 IPC，后者决定 Windows/Linux 内容内窗口按钮与拖动区域。窗口控制独立于聊天初始化，历史/配置/存储失败可提示和重试。

Windows 继续保留透明 WebView 合成、原生底色同步、DWM 圆角与贴边细边框；HTML 仅启动期间透明，加载或报错后的内容保持不透明。应用 identifier、安装目录、升级标识与图标唯一源不随社交界面重写改变。原生玻璃及新布局按本批实测范围记录，不把历史验收视为所有设备已通过。

构建仍将桌面前端输出到忽略的 `frontends/tauri/dist`，不修改已跟踪 Web dist 或强制提交生成权限 schema。目录打开能力继续限制为 config/data 枚举。

## 8. 验收

1. 私聊、群聊和联系人切换保留输入、表单与运行。
2. 一个空间生成时，另一个空间可发送并显示后台新消息。
3. 保存失败、模型不可用和订阅断线使用不同提示。
4. 暂停、取消和结束各自作用正确，按钮键盘可用且状态可读。
5. 页面隐藏不留下菜单 portal，订阅不会随切换重复建立。
6. Web、Windows IPC、Linux IPC 字段与行为一致；窗口和打包基线无回归。
7. 主导航仅消息/通讯录；两种详情的关系记忆编辑保持同步，群记忆始终具有空间归属。
8. 重复打开、归档恢复和模型切换保持私聊窗口唯一，摘要处理不删除历史。
9. 群消息接续私聊保留明确来源与未发送草稿，不重复创建窗口、不因点击而自动发送，也不回传私聊内容。
