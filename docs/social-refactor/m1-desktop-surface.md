日期：2026-10-10。属于 M1 第 4 条业务线「双适配与阶段收尾」。本批调整共用界面及桌面启动，不执行安装或卸载验收。

## 启动与快捷方式

原桌面和开始菜单快捷方式均指向现有安装目录的 `LLM-Nest.exe`，参数正常。桌面后端是内嵌 Rust Runtime，由首次 IPC 请求初始化，不需要另开 Web Server。

实际启动报错为 TOML 的 `missing field providers`：原配置只有注释，旧反序列化要求 providers 必须存在，因而消息/通讯录显示未连接。本批为 RuntimeConfig.providers 增加空集合默认值，空文件、仅注释和显式空表都可以启动；非法语法或字段类型继续报错。

为恢复仍在运行的旧安装版，先在仓库之外备份并逐字节核对原配置，确认其解析结果为空后只补充 `[providers]`。原窗口点击重试后读到真实本地账号与空聊天列表，没有创建模拟回答。配置内容、凭据和用户数据均未进入构建产物或提交。

## 界面与窗口

- Windows 启动时用透明原生底色和透明 HTML 露出 Acrylic；加载期间不显示标题或加载文案。成功、初始化失败或 React 错误后显现界面，保留具体错误、重试和设置入口，关闭控制独立可用。
- 社交页去掉独立 56px 标题栏，将窗口按钮放在内容右上角，并保留品牌区、聊天头部空白与顶部细窄区域的拖动属性。原 DWM 边框、圆角及上下贴边逻辑继续保留，不增加阴影外边距。
- 参考 [Codex 官方界面](https://openai.com/index/introducing-the-codex-app/) 的连续表面与紧凑侧栏，将导航、聊天/联系人列表和自己的账号合为 288px 侧栏；保留消息/通讯录两个主入口。
- 中性灰白 / 炭黑、克制蓝色、800px 聊天宽度、无外框 AI 正文、柔和灰色用户气泡及低阴影输入区。真实与预览共享侧栏呈现，业务和数据适配器仍独立。
- 手机宽度进入聊天时隐藏整个侧栏，避免底部账号/设置浮在输入区上。窄窗口初始化失败仍显示错误和重试，桌面错误区为窗口按钮留出空间。
- Linux 源码关闭系统标题栏，使用共用窗口按钮和窗口状态事件；启动仅为主题底色空白层。本批没有 Linux 构建或 GNOME 实机复验，不声称已有 Windows 原生玻璃效果。

为了让原快捷方式打开新界面，本机现有程序文件先在仓库外备份，再替换为当前工作区构建。保留安装目录、快捷方式、卸载登记及原 NSS 标记；除该三字节标记外逐字节匹配生产 EXE。空环境 worker 的 add 与拒绝 shell 检查通过。原桌面快捷方式实际打开新社交界面并显示「记录持续保存」。这属于本机程序文件更新，没有运行 NSIS、MSI、安装或卸载；历史安装包不据此成为新 UI 的发布包。

截图、构建日志、程序更新核对和隔离测试数据留在忽略的 `target/ui-surface-qa` / `target/ui-surface-build.log`，不提交测试数据或私人路径。
