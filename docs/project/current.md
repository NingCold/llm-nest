# 当前安排

[已完成](completed.md) · [待验收与候选](backlog.md) · [拆仓计划](repository-split-plan.md) · [使用指南](../usage.md)

当前处理输入本机口令后约 10 秒的解锁等待。客户端已改为：已有可信设备打开本机密钥库、通过服务器设备有效性检查后即可进入聊天，收件箱、公钥查询和备份继续在后台完成。服务端用递增的设备目录版本避免把未变化的设备反复报告给 SDK；兼容旧客户端、旧服务端和现有 Agent，不降低口令保护强度。

本地 Windows 已通过 NSIS 更新至 `alpha.16`，随包 Agent 仍为 `alpha.14`；升级前后 84 个日常持久文件 SHA-256 一致。内网服务端 `alpha.13` 与 Web `alpha.16` 已部署，原数据库和附件核对保持。用户反馈解锁主观约 5 秒；真实 WebView 中 `unlockCrypto` 为 1935ms，其中开本机库 1506ms，后台同步 429ms。函数计时不等于点击至界面出现的全程，剩余体感等待仍待端到端测量；本批尚未推送或公开发布。

自动检查、完整加密与历史迁移回归通过，真实模型调用为 0。原理、具体结果和计时入口见[解锁等待优化](../validation/README.md#解锁等待优化)，安装结果见[Windows 记录](../validation/windows.md#解锁与设备目录同步优化2026-11-01)。

桌面创建加密 AI、恢复文件与双方信任、首份角色模型应用、同机私聊和节点额度编辑已可使用；此前桌面验收保留在[验证记录](../validation/windows.md#桌面创建加密-ai-与额度2026-11-01)。三仓拆分及公开 Alpha 的历史发布结果见[第三批验证](../validation/README.md#拆仓第三批验证)。

当前同步已不再阻塞锁屏；函数内主要耗时为开本机库，口令派生与 IndexedDB 尚未分别计时。后续按日常反馈核对剩余等待，不将约 5 秒体感记为问题完全解决。可选自动解锁未开启；30 天到期、离线重启、干净 Windows、Linux GNOME 人工验收及独立安全审查继续保留在[待验收](backlog.md#待验收)。第三方 Agent 接入 SDK 和局域网直连是未排期待办，不并入本轮。
