# 08 界面与桌面

[总纲](README.md) · [API 与事件](07-api-and-events.md) · [运行时与配置](09-runtime-and-configuration.md)

状态：目标设计，尚未实现。React 源码继续只维护在 `frontends/web`。

## 1. 信息结构

主导航只有“消息”和“通讯录”两个入口。消息页显示持续私聊与独立群聊，通讯录显示稳定 AI 联系人；设置通过独立按钮进入，记忆管理嵌入聊天详情和联系人详情。首版不增加记忆主导航、公开广场或推荐信息流。

| 区域 | 默认展示 | 详情与操作 |
| --- | --- | --- |
| 消息列表 | 名字/群名、头像、最后完整消息、未读与置顶 | 暂停标记、归档、搜索 |
| 私聊顶部 | 对方身份、参与状态 | 档案、共同记忆、主动联系设置 |
| 群聊顶部 | 群名、成员 | 入群历史范围、成员模式、群记忆 |
| 通讯录/联系人详情 | 身份档案、唯一私聊入口 | 相处设置、关系记忆与执行配置 |
| 消息正文 | 发送者、时间、回复对象、正文或附件 | 编辑修订、撤回、再次回应、来源、与某 AI 私聊继续 |
| 运行详情 | 可折叠的执行状态 | 用量、计时、思考、工具与错误 |

模型选择、reasoning effort、temperature 和工具授权移到 AI 档案的高级配置。常规聊天仍显示明确的 AI 标记，不用模型名替代角色名。更换模型后的行为差异通过配置变更提示表达，不声称人格必然完全一致。

## 2. 路由与组件落点

主入口路由为 `#/messages` 和 `#/contacts`。聊天使用 `#/messages/{conversationId}`，聊天详情及记忆使用 `#/messages/{conversationId}/details` 与其 `/memories` 子页；联系人详情使用 `#/contacts/{actorId}`，关系记忆位于其 `/memories` 子页。现有 `#/settings/models|generation|appearance|config|about` 保留。`#/chat` 在迁移完成后兼容跳转到最近空间；未知或无权访问的 ID 显示可恢复状态。

点击同一联系人始终打开同一个私聊 ConversationId；群列表每项打开对应独立群窗口。结束当前交谈、更换模型或切换话题不清空记录，也不新增联系人私聊。

M2 在群消息菜单加入“与某 AI 私聊继续”：选择拥有该段群历史访问权的 AI，打开其唯一私聊，在输入区带上可查看来源的引用条，发送后与用户消息一起保存。用户可调整或移除选中的范围；切换窗口后未发送引用随该私聊草稿保留，单纯导航不会自动发消息。AI 无源访问权时改为用户明确选择转发内容，不把源群全文直接注入私聊。

组件按领域拆分为 contacts、conversations、messages、memory、participation 与 settings。布局重写现有 Sidebar/Header/ChatView 的业务部分，继续复用基础 UI、Markdown、代码与 Mermaid 渲染。

输入草稿按 conversationId 保存；档案和设置表单按对象保存。切换页面不会停止运行、清空输入或重复建立订阅。隐藏聊天 Header 时卸载菜单 portal，避免覆盖其他页面。

## 3. 状态管理

| Store | 负责内容 |
| --- | --- |
| actorStore | 档案、执行可用状态与联系人列表 |
| conversationStore | 空间摘要、成员、当前空间与已读位置 |
| messageStore | 分页消息、临时发送记录与修订 |
| runStore | 按 RunId 管理生成片段、活动与终态 |
| memoryStore | 范围筛选、候选确认、修改与遗忘 |
| participationStore | 暂停、成员模式、交谈与联系意图 |
| connectionStore | 订阅生命周期、cursor、重连与补齐状态 |

取消全局 isStreaming 对所有输入的阻塞。输入是否可发送取决于当前空间访问、历史加载、附件状态和存储连接；AI 生成状态单独管理。

目标契约允许先保存真人消息，再判断 AI 是否可执行。无模型时给出“消息已保存，该 AI 需要配置”的明确状态；在 M1 切换完成前，现有无模型禁止发送规则继续生效，届时同时修订 AGENTS 与验收。

## 4. 发送、流式与重连

用户点击发送后创建 clientRequestId 对应的临时消息，状态为 sending；保存成功后替换为服务器 UUID 和 message_seq，失败保留 failed_to_send 与可重试内容。

真人消息保存成功不预建 AI 消息。后端 run.started/message.created 到达后建立生成展示，标明谁正在输入、回应哪条消息。生成期间用户可继续输入和发送。

消息持久状态与传输状态分开。SocialMessage 的 complete/cancelled 等状态不能与发送失败混用；最终记录覆盖临时缓冲。新消息未读以完整可见消息为准，自身消息不增加未读。

订阅在应用级维护一个实例，页面读取共享 store。持久事件按 ID 去重并按 cursor 顺序应用；状态获取失败先重试或重新快照，不提前推进 cursor。终态后不接受旧 delta。

重连时显示连接与补齐状态，先恢复服务器权威记录和活动运行；不继续拼接断线前无法核对的 token，也不把断线展示为 AI 主动结束聊天。

## 5. 三种停止操作

- “停止这次回复”：cancelRun，只中断选定运行。
- “暂停 AI 参与”：pauseMember 或 pauseConversation，停止后续自动回应；真人仍可记录消息。
- “结束本次聊天”：endBout，保留关系与空间，取消当前接话队列。

这些操作在按钮、菜单和状态文本中明确区分。暂停后的恢复是显式动作；约定联系是否继续在详情中可见，关闭主动联系会取消相应意图。

## 6. 记忆与资料管理

私聊详情与联系人详情访问同一份关系记忆；群详情管理本群记忆。联系人详情中的群记忆入口跳转到对应群，按权限展示，不把各空间记忆默认混合成一个公共档案。

首个记忆面板显示文本、范围、来源、有效状态和更新时间，提供添加、编辑和遗忘；后续自动候选加入后提供确认/拒绝。群里的共同记忆与私聊记忆分别展示，分享内容需要用户明确选择。近期消息与历史摘要可在聊天详情解释来源，完整原记录保留在消息列表。

聊天详情中的“历史摘要”按窗口显示分段、覆盖范围与更新状态。未来联系人详情可提供角色/关系“记忆概览”，它汇总该视角允许使用的信息，与聊天摘要分别标注。跨窗口接续在消息中显示可跳转的群来源，后续私聊内容不自动共享回群。

AI 创建流程先填写身份，再选择执行配置；可以保存未配置模型的档案。群创建与邀请时说明历史范围。归档、撤回、清除历史与遗忘的影响分别表达，不使用一个含糊的“重置”按钮覆盖全部行为。

异步记忆提取失败有独立任务状态，不能把已经完成的回答显示为失败。角色和关系数据保存失败保留表单草稿，提供明确重试。

## 7. 平台约束

Tauri 与 Web 共用组件和 SocialApi。demo 使用明确标记的模拟数据与独立存储，不能自动替代失败的真实后端，也不能用 demo 验收证明数据库或调度成功。

首版不新增托盘或隐形常驻服务。窗口最小化时运行时仍可执行；应用实际退出后主动联系停止。关闭窗口沿用当前宿主语义，退出时由 Runtime 完成中断收尾。后续后台常驻需要独立的设置、状态与验收。

保留 IS_DESKTOP 与 CUSTOM_WINDOW_CHROME 的区别，Linux 使用桌面 IPC 与系统装饰。窗口控制独立于聊天初始化，历史/配置/存储失败可提示和重试。

Windows 已验收的透明 WebView 合成、不透明 HTML、原生底色同步、DWM 圆角与贴边细边框继续保留。应用 identifier、安装目录、升级标识与图标唯一源不随社交界面重写改变。

构建仍将桌面前端输出到忽略的 `frontends/tauri/dist`，不修改已跟踪 Web dist 或强制提交生成权限 schema。目录打开能力继续限制为 config/data 枚举。

## 8. 验收

1. 私聊、群聊和联系人切换保留输入、表单与运行。
2. 一个空间生成时，另一个空间可发送并显示后台新消息。
3. 保存失败、模型不可用和订阅断线使用不同提示。
4. 暂停、取消和结束各自作用正确，按钮键盘可用且状态可读。
5. 页面隐藏不留下菜单 portal，订阅不会随切换重复建立。
6. Web、Windows IPC、Linux IPC 字段与行为一致；窗口和打包基线无回归。
7. 主导航仅消息/通讯录；两种详情的关系记忆编辑保持同步，群记忆始终具有空间归属。
8. 重复打开、归档恢复和模型切换保持私聊窗口唯一，摘要处理不删除历史。
9. 群消息接续私聊保留明确来源与未发送草稿，不重复创建窗口、不因点击而自动发送，也不回传私聊内容。
